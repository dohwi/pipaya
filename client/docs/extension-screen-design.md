# 확장 화면 디자인 규격

확장이 그리는 모든 화면(확장 화면 패널, 입력창 위젯, 헤더 항목)과 이를 관리하는 설정 → 확장 화면의 디자인 기준입니다. 구조·코드 위치는 [extension-architecture.md](extension-architecture.md), 노드 타입 규칙은 [extension-ui.md](extension-ui.md)입니다.

## 0. 전제: 모양은 호스트가 책임진다

확장은 HTML·CSS·클래스·URL을 보낼 수 없고 **데이터(view tree)만** 보냅니다. 따라서

- 확장이 못생겨 보이는 원인은 거의 항상 **호스트 렌더러**(`ExtensionView.svelte` 등)입니다. 모양은 중앙에서 한 번 고치면 모든 확장에 적용됩니다.
- 새 스타일이 필요하면 확장에 CSS를 열어 주지 말고 **새 노드·새 enum 값(tone, size, gap)** 을 추가합니다.
- 앱은 확장 화면의 **출처(확장 이름)** 를 항상 표시합니다. 확장이 앱의 승인창이나 설정창처럼 보이지 않게 하는 보안 장치이므로, 디자인 정리를 하더라도 출처 표시는 없애지 않습니다.

## 1. 화면 지도

| 표면 | 위치 | 컨테이너 | 대화형 | 소유 |
|---|---|---|---|---|
| **확장 화면** | 무대(stage) 우상단 런처 → 모달 | 네이티브 `<dialog>`, `min(1000px,96vw)` × `min(760px,90dvh)` | O | `ExtensionPanels` |
| **입력창 위젯** | 입력창 위, 접이식 박스 | `Accordion variant="box"`, 최대 높이 `min(40dvh,320px)` 스크롤 | O | `ExtensionPanels placement="composer"` |
| **헤더 항목** | 헤더 우측 슬롯 | 폭 `min(40%,160px)`(≤600px: `min(36%,132px)`), 가로 스크롤 | X (읽기 전용) | `NavbarUsage` |
| **상태 칩** | 입력창 아래 상태 줄 | 텍스트 칩 | X | `StatusLine` |
| **입력창 액션** | 입력창 아래 | 작은 버튼 줄 | 클릭만 | `Composer` |
| **관리 화면** | 설정 → 확장 | 설정 모달의 탭 | O | `Extensions.svelte` |
| **가져오기 미리보기·결과** | 설정 위 모달 | 자체 모달(z 80/81) | O | `Extensions.svelte` |
| **승인창** | 앱 전역 | `<dialog>` | O | `ExtensionApproval` |

### 확장 화면 레이아웃

```
┌──────────────────────────────────────────────────────────┐
│ 확장 화면 · {확장 이름}                                ✕ │ header  (bg-side, 20/24 padding)
│ 확장에서 제공하는 별도 화면입니다.                       │
├──────────────────────────────────────────────────────────┤
│ (1) ‹ [패널A | 확장] [패널B] ›                           │ rail    (패널이 있을 때, 칩 높이 32)
├──────────────────────────────────────────────────────────┤
│  {확장 이름}            ← eyebrow (mono 10px)            │
│  패널 제목              ← h3 20px                        │ surface-heading
│  패널 설명 ─────────────────────────────────────         │
│                                                          │
│  [view tree]            ← ExtensionView                  │ body (28px, 모바일 20/16)
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 관리 화면 카드

```
접힘:  ┌ › 확장 이름  v1.0.0                       (●━) ┐   행 = 이름 + 버전 + 스위치
펼침:  │ 설명                                            │
       │ example.ui-workbench            (mono, faint)   │
       │ [다시 불러오기] [내보내기]            [삭제]    │
       │ ▸ 권한과 실행 안내                              │   Accordion (기본 접힘)
       │ ▸ 확장 설정                                     │   (필수 설정이 비었으면 기본 펼침)
       └─────────────────────────────────────────────────┘
```

경고·오류는 카드 상단에 `callout`으로 붙습니다: 시작 오류(`danger`), "켤 수 없습니다. {이유}"(`warn`).

## 2. 디자인 원칙

1. **차분한 단색 + 대비로 강조.** 앱 전체가 무채색 팔레트이고 accent는 색조가 아니라 명도 대비(`--accent` = 거의 흰색/검정)입니다. 색은 **의미(ok/warn/danger/info)** 에만 씁니다.
2. **한 화면에 주 행동은 하나.** `primary` 버튼은 화면(폼)당 하나. 나머지는 `secondary`, 파괴적 동작만 `danger`.
3. **상태는 반드시 설계한다**: 초기, 로딩, 빈 상태, 성공, 실패, 비활성. 빈 상태는 "무엇을 하면 채워지는지"를 말합니다.
4. **복구 가능성 우선.** 입력은 실패해도 보존하고, 파괴적 동작은 확인을 거치고(포커스는 안전한 선택지), 설정 값을 어떻게 할지 묻습니다.
5. **작은 화면이 기본.** 320–390px에서 먼저 성립해야 합니다. 가로 스크롤은 표·코드·헤더 슬롯처럼 의도한 곳에서만.
6. **움직임은 의미가 있을 때만.** 등장 360ms/퇴장 180ms 토큰을 쓰고 `prefers-reduced-motion`에서 끕니다.
7. **정보 중복 금지.** 같은 이름(확장·패널 제목)을 한 화면에서 세 번 보여주지 않습니다. 출처는 한 번, 분명하게.

## 3. 디자인 토큰

원본은 `src/app.css`의 `:root`입니다. 컴포넌트는 값을 하드코딩하지 않고 토큰을 씁니다. (확장 테마가 바꿀 수 있는 것은 [extensions.md](extensions.md#테마)의 화이트리스트뿐.)

| 구분 | 토큰 | 값 |
|---|---|---|
| 반경 | `--radius` / `--radius-panel` / `--radius-sm` / `--radius-pill` | 12 / 16 / 8 / 999px — 카드 / 모달·패널 / 컨트롤 / 버튼·칩 |
| 모션 | `--motion-fast` / `-normal` / `-slow` | 180 / 360 / 460ms |
| 이징 | `--ease`(등장) / `--ease-exit` / `--ease-std` | 감속 / 가속 / 표준 |
| 면 | `--bg` → `--bg-side` → `--bg-elev` → `--bg-hover` → `--bg-active`, `--bg-code` | 어두운 순서가 아니라 **깊이** 순서 |
| 선 | `--border`(구분) / `--border-strong`(컨트롤·강조) | |
| 글자 | `--text` / `--text-dim` / `--text-faint` | 본문 / 보조 / 힌트 |
| 의미색 | `--ok`·`--warn`·`--danger` + `*-soft`(tint), `--lv-low`(info) | |
| 폰트 | `--font`(Manrope, SUIT) / `--mono`(JetBrains Mono) | 코드·ID·수치에 mono |
| 그림자·스크림 | `--shadow`, `--scrim` | 모달 |
| 안전 영역 | `--sat/sab/sal/sar` | 모바일 노치 |

### 간격·크기 (현재 구현 값)

| 요소 | 값 |
|---|---|
| `stack` gap | small 6 / medium 12(기본) / large 20px |
| `grid` | 열 1–3, 최소 열 폭 9rem(그보다 좁으면 자동 감소), gap 12 |
| `card` | padding 14×16, 내부 gap 12 |
| 폼 | 필드 간 14, 필드 내 라벨–입력 5 |
| 입력 컨트롤 | padding 8×10, **글자 16px**(iOS 확대 방지), 테두리 `--border-strong`, 포커스 시 `--accent` + 3px `--accent-soft` 링 |
| 버튼 | 최소 높이 36(관리 화면 `sm` 34), 알약, 13–13.5px 600 |
| 패널 본문 | padding 28(≤640px: 20×16) |
| 게이지 | small 26px(≤600px 22px), medium 48px |

## 4. 컴포넌트별 규격

| 노드 | 용도 | 쓸 때 | 피할 것 |
|---|---|---|---|
| `stack` | 수직/수평 묶음 | 기본 뼈대. 수평은 줄바꿈 허용 | 깊은 중첩(깊이 8, 노드 200 한도) |
| `grid` | 같은 성격의 카드 나열 | stat·카드 2–3열 | 서로 다른 성격 혼합 |
| `card` | 제목 있는 그룹 | 화면을 의미 단위로 나눌 때 | 카드 안 카드, 카드 안 큰 표 |
| `tabs` | 같은 층위의 대안 화면 | 2–8개, 라벨 짧게 | 순서가 있는 단계(→ 폼 + 상태) |
| `form` | 값 일괄 제출 | 제출 버튼 문구는 **동사형**("입력창에 초안 넣기") | 중첩 form, "확인"만 쓰기 |
| `text` | 설명 | `heading`은 화면당 1–2개 | `tone`으로 색만 바꿔 의미 전달 |
| `badge` | 짧은 상태 라벨 | 1–2단어 | 문장 |
| `alert` | 결과·안내 | 성공/실패 피드백, `danger`·`warning`은 `role=alert`로 낭독됨 | 상시 장식 |
| `stat` | 핵심 수치 | 라벨 + 값 + (선택) 힌트, 한 그리드에 3–4개 | 값에 긴 문장 |
| `progress` | 진행률 | 길이를 아는 작업 | 알 수 없는 대기(→ 텍스트로 "불러오는 중") |
| `gauge` | 사용량·한도 | 헤더(small), 상세는 `details` | 값을 모를 때 0으로 보내기(`null`) |
| `table` | 비교용 데이터 | 열 ≤8, 캡션 제공, 셀은 짧게 | 100행 이상, 열이 많은 모바일 의존 |
| `list` | 항목 + 보조 정보 | `emptyText` 제공 | 대화형 목록(항목은 클릭 불가) |
| `code` | 코드·로그 | 가로 스크롤, 포커스 가능 | 길이 16,000자 초과 |
| `button` | 단발 동작 | 문구는 동사, 위험 동작은 `danger` | 같은 화면에 `primary` 여러 개 |
| `input`/`textarea`/`select`/`checkbox` | 입력 | 라벨 필수, `required`·`error` 사용 | 라벨 대신 placeholder |
| `icon` | 데이터 기반 벡터 | 의미를 `label`로 제공(장식이면 생략) | 8경로·8,192자 초과 |

헤더(navbar)는 `stack`·`grid`·`text`·`badge`·`divider`·`progress`·`stat`·`gauge`·`icon`만 허용합니다(대화형 금지).

## 5. 상태 설계

| 상태 | 패널에서 | 관리 화면에서 |
|---|---|---|
| 초기 | 무엇을 하는 화면인지 한 줄 + 첫 행동 | 빈 목록: 점선 카드 + "확장 추가" 안내 |
| 로딩 | `progress` 또는 `text`("불러오는 중…"), 버튼 비활성 | 행 오른쪽 스피너(`role=status`) |
| 빈 데이터 | `list.emptyText`, 표는 "표시할 행이 없습니다" | 읽을 수 없는 항목은 별도 카드로 보관 |
| 성공 | `alert tone=success`, 이유와 다음 행동 | 상단 `callout ok`(저장했습니다 …) |
| 실패 | `alert tone=danger` + 재시도 가능한 입력 보존. 호스트는 "{확장 이름} ({id})" 귀속과 함께 오류 박스 표시 | 카드 상단 `callout danger` |
| 비활성 | 버튼 `disabled`(불투명도 .55), **이유를 근처에 텍스트로** | 스위치 비활성 + "켤 수 없습니다. {이유}" |
| 오프라인·서버 없음 | 입력창 위젯은 서버가 없으면 아예 안 보임 | 동기화 안내 `callout warn` |

## 6. 접근성 · 반응형 · 모션

**호스트가 이미 보장**: 실제 `<label>`, 네이티브 컨트롤, 표 의미 구조, 탭 키보드(←/→/Home/End), 오류 `aria-live`·`aria-invalid`·`aria-describedby`, 모달 포커스 트랩·Esc·닫을 때 런처로 포커스 복귀, 스크롤 영역(`tabindex=0`), 게이지 `progressbar`+`aria-description`.

**확장 작성자가 책임**: 명확한 라벨·버튼 문구, 오류 문구가 해결 방법을 말하는지, 색만으로 의미를 전달하지 않는지.

**기준(앞으로 지킬 것)**

- 본문 글자 대비 4.5:1 이상. 현재 토큰 계산값은 [§8-3](#8-현재-구현-리뷰-2026-10-13) 참고.
- 터치 대상은 모바일(Tauri Android 포함)에서 **40–44px 이상** 목표. 현재 CSS 값: 패널 칩 32, 이전/다음 28(모바일에서는 숨김), 버튼 34–36.
- 글자 크기는 **11px 미만 금지** 권장. 현재 10px 사용처: 패널 `eyebrow`, `owner`, `count`.
- 중단점은 640px(모달·카드·패널) 하나와 600px(헤더 슬롯·게이지) 하나가 섞여 있습니다. 통합하거나 이유를 남기세요.
- 모달은 `<dialog>.showModal()`(top layer). **그 안에서 떠야 하는 것(팝오버, 툴팁)은 `<body>`가 아니라 열린 dialog 안에 붙입니다**(`ExtensionGauge`가 그렇게 합니다).

## 7. 확장 작성자를 위한 화면 레시피

**대시보드**: `stack(large)` → `alert`(상태 한 줄) → `grid(columns:3)`의 `stat` 3–4개 → `tabs`(요약/상세) → `table`. 값이 갱신될 때는 같은 노드 ID로 `ui.update`.

**작성 폼**: `card(title, description)` 안에 `form`. 필드는 위에서 아래로 "필수 → 선택", `submitLabel`은 결과를 말하는 동사. 제출 후 `alert`로 결과 + 입력 유지.

**상시 지표**: 헤더에 `gauge(size:small)` 1–3개, 자세한 수치는 `details`(행 ≤12, `updatedAt` 제공, 모르는 값은 `null`).

**규칙 모음**

- 노드 ID는 의미 기준으로 **안정적으로** 유지(편집 중 값·포커스 보존). 필드를 초기화하려면 새 ID.
- 패널 제목은 확장 이름과 달라야 하고(같으면 호스트가 출처 줄을 생략) 설명은 한 문장.
- 한 화면의 노드 예산: 200개 중 **80 이하**로 설계(렌더·스크린리더 부담). 표·목록 100행은 상한이지 목표가 아님.
- 폼 값은 민감정보로 취급, `console` 출력(= 확장 로그)에 값을 싣지 않기.
- 레이아웃이 아니라 **내용**으로 우선순위를 표현(제목·순서·tone). 장식용 `badge`·`divider` 남발 금지.

## 8. 현재 구현 리뷰 (2026-10-13)

방법: 개발 서버(`0.0.0.0:1420`)에서 Playwright로 UI 워크벤치 예제를 설치·활성화하고 데스크톱 1280×820 / 모바일 390×780, 다크·라이트로 캡처해 직접 확인했습니다. **서버를 연결하지 않은 상태라 입력창 위젯·헤더 navbar·상태 칩·입력창 액션은 화면으로 확인하지 못했고(코드만 검토), `ExtensionApproval`도 화면 미확인입니다.** 심각도는 사용자 영향 기준(높음/중간/낮음)입니다.

### 8-1. 잘 된 점 (유지)

- 관리 화면의 **접힌 행**(이름·버전·스위치)과 펼침 정보 계층. 파괴적 동작은 오른쪽 끝에 분리, 삭제 확인은 안전한 선택지에 포커스.
- 입력 오류 처리: 필드별 문구, 포커스 이동(숨은 탭 안 필드 포함), 실패 시 입력 보존.
- 호스트 오류에 확장 이름·ID 귀속, 경고/오류의 `callout` 시각 일관성.
- 입력 컨트롤 16px, 포커스 링, `prefers-reduced-motion` 대응.
- 모달 모션과 슬라이딩 선택 표시가 앱 전체와 일관.

### 8-2. 문제와 개선안
