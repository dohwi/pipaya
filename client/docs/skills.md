# 스킬

입력창 아래 상태 줄의 책 모양 아이콘(스킬 개수)을 누르면 스킬 창이 열립니다.

## 어디서 불러오나요

| 종류 | 위치 |
|---|---|
| 전역 | 서버 사용자 홈의 `~/.agents/skills/` |
| 프로젝트 | 대화의 작업 디렉터리부터 git 루트까지의 `.pi/skills/`, `.agents/skills/` |
| 기본 내장 | 서버에 포함된 `builtin-skills/`. 모든 프로젝트에서 기본으로 켜져 있고(현재: `harness-client-extensions` — 클라이언트 확장 기능 작업 안내, `harness-usage` — 서브에이전트·AGENTS.md·스킬 사용법) 창에서 끌 수 있습니다 |

이름이 같으면 더 가까운 폴더, 그다음 프로젝트·전역 스킬이 기본 내장보다 우선합니다(같은 이름으로 바꿔치기해도 경고는 없습니다). 읽지 못한 스킬은 창 위쪽에 경고로 표시됩니다.

## 켜기 / 끄기

- **이 프로젝트**: 현재 프로젝트에서만 켜고 끕니다. 전역 기본값과 같게 돌리면 기본값을 따르고, `되돌리기`로도 해제할 수 있어요.
- **모든 프로젝트**: 전역 기본값입니다. 프로젝트에서 따로 정한 스킬은 바뀌지 않습니다.
- `disable-model-invocation: true`인 스킬은 `수동 전용`으로 표시되며 켜고 끌 수 없습니다.

설정은 서버에 저장되어 같은 서버에 연결한 모든 클라이언트가 공유합니다.

## 언제 적용되나요

켜고 끈 설정은 **다음 메시지부터** 진행 중인 대화에도 바로 적용됩니다(새 대화일 필요가 없어요). 푸터의 스킬 개수와 스킬 창도 같은 기준이라 항상 일치합니다.

- 설정이 바뀌지 않았다면 시스템 프롬프트도 그대로라서 프롬프트 캐시가 유지됩니다. 켜고 끈 직후 첫 응답에서만 캐시가 한 번 다시 만들어져요.
- 스킬을 끄면 모델에게 목록이 사라지고, 그 스킬 폴더를 읽는 것도 막힙니다. 이전에 읽은 내용은 대화 기록에 남아 있습니다.
- AGENTS.md는 예전처럼 첫 메시지 때 고정됩니다.

`read` 도구를 끈 대화에서는 스킬을 읽을 수 없으므로 스킬을 알려주지 않습니다(개수 0).

## 상태 줄

대화 중에는 그 대화에 지금 적용되는 스킬 수, 새 대화 화면에서는 선택한 디렉터리에서 다음 대화가 사용할 스킬 수를 보여줍니다. 스킬 기능이 없는 서버에서는 표시하지 않아요.

## 직접 호출: `/skill:이름`

입력창에서 `/`를 누르면 명령 아래에 켜진 스킬이 `/skill:이름` 형태로 **`스킬` 태그와 강조색**으로 구분되어 나옵니다. 고르면 입력창에 `/skill:이름 `이 채워지고, 뒤에 요청을 이어서 보내면 됩니다. 일반 명령처럼 바로 실행되지 않습니다.

- 서버가 메시지에서 `/skill:이름`(공백 뒤, 켜진 스킬만)을 찾아 그 `SKILL.md` 내용을 숨은 안내(`<harness-hint>`)로 함께 보냅니다. 대화 화면에는 보이지 않습니다.
- 모델이 스스로 고르길 기다리지 않아도 되고, `수동 전용` 스킬도 이 방법으로 쓸 수 있습니다.
- 꺼진 스킬이나 없는 이름은 평범한 글자로 취급됩니다. 한 메시지에 여러 개를 쓸 수 있습니다.
- 내용은 40,000자에서 잘리며, 잘리면 파일에서 나머지를 읽도록 안내합니다.
