작업이 끝나거나 승인이 필요할 때 알림을 받는 방법, 새 기기를 연결하는 방법, 기기를 해지하는 방법을 설명합니다.

## 알림 종류

| 종류 (`kind`) | 언제 |
|---|---|
| `task_completed` | 실행이 끝남. 제목에 "작업 완료", 본문에 답변 미리보기(공백 정리·최대 110자)와 걸린 시간 |
| `task_failed` | 오류로 멈춤. 오류 원인을 본문에 |
| `approval_required` | 도구 실행 승인을 기다림. "○○ 실행 승인을 기다리고 있습니다" |
| `user_request` | 에이전트가 질문(`ask_user`)을 하고 답을 기다림 |
| `info` | 확장 등이 보내는 일반 알림 |

알림 문구는 **받는 기기의 언어**(한국어·영어)로 서버가 직접 씁니다. 앱이 닫혀 있을 때 도착하는 푸시는 앱을 거치지 않기 때문입니다. 제목은 "무슨 일이 어느 대화에서"를, 본문은 결과 미리보기를 담아 앱을 열지 않고도 판단할 수 있게 합니다.

## 누구에게 가는가

서버는 접속 중인 기기마다 **상태**를 알고 있습니다. 기기는 주기적으로(하트비트) `PUT /notifications/devices/:id`로 자기 상태를 보고합니다.

| 필드 | 설명 |
|---|---|
| `platform` | `desktop` `android` `ios` `web` |
| `focused` | 지금 앱 창을 보고 있는지 |
| `enabled` | 이 기기가 알림을 받을지 |
| `visibleSessionIds` | 화면에 보이는 대화 (최대 20개) |
| `lang`, `name`, `os`, `app` | 표시·문구용 정보 |
| `push` | 모바일 푸시 토큰 `{provider: "fcm" \| "apns", token}` (모바일만) |

판단 규칙은 다음과 같습니다.

| 상황 | 동작 |
|---|---|
| 어느 기기든 **앱을 보고 있음** | 알림을 보내지 않음 (OS 알림·푸시 모두 억제) |
| PC·웹이 접속 중 | 그 기기에 OS 알림 |
| 푸시가 설정된 모바일이 있음 | 모바일 푸시 |
| 이미 PC에 알림이 갔는데 아무도 안 봄 | 설정한 시간 뒤 폰으로 **에스컬레이션** |

- 보고 있는 대화가 끝날 때는 울리지 않습니다. **승인 요청은 보고 있어도 소리가 납니다.**
- 기기 상태는 **45초** 동안 하트비트가 없으면 접속이 끊긴 것으로 봅니다.
- 모바일은 "보고 있음"을 **25초**까지만 인정합니다. 다른 앱으로 전환하면 WebView가 얼어붙어 "안 보고 있음" 보고가 못 올 수 있기 때문입니다.
- PC가 알림을 표시했다는 확인(`POST /notifications/:id/received`)을 **5초** 기다린 뒤 모바일 푸시를 보냅니다. 표시할 수 있는 기기가 없는 모바일은 1초만 기다립니다. 그사이 실행이 다시 시작되면 푸시가 취소됩니다.
- 같은 `source:key`의 알림은 **24시간** 동안 중복 전송되지 않습니다.
- 서버가 꺼져 있던 사이에 지난 에스컬레이션은 10분이 넘으면 버립니다.

### PC에서 읽지 않으면 폰으로

설정 → 일반 → 알림의 **PC에서 읽지 않으면 폰으로**는 에스컬레이션 대기 시간입니다. PC로 알림이 갔는데 이 시간 동안 어느 기기에서도 앱을 열어 보지 않으면 폰으로 푸시합니다. 값은 `보내지 않음`, 1, 2, 3(기본), 5, 10, 15, 30, 60분 중에서 고르며, **이 서버에 연결한 모든 기기에 같이 적용**됩니다(서버 설정 `notificationPolicy`).

## 알림 설정

설정 → 일반에서 합니다.

| 항목 | 설명 |
|---|---|
| 시스템 알림 | 작업 완료·실패·승인 필요·사용자 요청 때 OS 알림. 앱 창을 보고 있으면 보내지 않음 |
| 이 기기로 시험 알림 보내기 | 서버 → 앱 → OS 경로를 한 번 점검. 실패 단계를 구체적으로 알려 줌 |
| 모바일 푸시 상태 | 서버 푸시 설정 여부와 이 기기의 토큰 유무 |
| 알림음 | 작업 완료·확인 필요·실패 때 소리. 크기 0~200%, 기본 100% |
| PC에서 읽지 않으면 폰으로 | 위 에스컬레이션 시간 |

시험 알림이 실패하면 원인이 구분되어 나옵니다: 시스템 알림 스위치가 꺼짐 / 운영체제가 알림을 막음 / 서버가 이 기기를 모름 / 서버가 시험 요청을 못 받음(서버가 이전 버전일 수 있음) / 서버는 보냈지만 6초 안에 앱이 못 받음(실시간 연결 끊김) / 앱이 OS에 넘기지 못함.

## 모바일 푸시 (FCM)

앱이 완전히 닫혀 있을 때도 받으려면 서버에 푸시가 설정되어 있어야 합니다.

| 조건 | 설명 |
|---|---|
| `PIPAYA_PUSH_FCM` | `0`이 아니면 켜짐 (기본 켜짐) |
| 자격 증명 | `GOOGLE_APPLICATION_CREDENTIALS` 환경 변수가 가리키는 파일, 없으면 `~/.secrets/pipaya/firebase-adminsdk.json` |
| 동작 조건 | 위 자격 증명이 **실제로 있어야** 동작함. 없으면 푸시는 조용히 꺼져 있음 |
| 확인 | `GET /notifications/status` → `{pushConfigured, providers}` |

기기별 푸시 토큰은 서버 DB(`notification_devices`)에 저장되며 최대 100대까지 관리합니다. 푸시 토큰 값은 API로 돌려주지 않습니다.

> [!NOTE]
> 앱이 종료된 상태의 모바일 푸시는 네이티브 푸시 등록과 서버 FCM/APNs 설정이 모두 필요합니다. 설정이 없으면 설정 화면에 "아직 연결되지 않았습니다"라고 표시됩니다.

## 확장이 보내는 알림

클라이언트·서버 확장은 `system-notifications` 권한으로 알림을 보내거나 **알림 규칙**을 등록할 수 있습니다.

| 항목 | 값 |
|---|---|
| 직접 보내기 | `POST /notifications` `{source, notification:{title, body?, kind?, sessionId?, key?}}` |
| 제목 / 본문 | 제목 최대 183자(앞에 `[소유자]`가 붙음), 본문 최대 300자 |
| 속도 제한 | `source`당 **10초에 5회** |
| 예약된 소스 | `pipaya`는 내장 알림용이라 확장이 쓸 수 없음 |
| 규칙 | `PUT /notifications/rules/:owner/:id` `{event: "run_finished" \| "approval_requested", title, body?}`. 소유자당 **최대 5개** |
| 규칙 삭제 | `DELETE /notifications/rules/:owner/:id`, `DELETE /notifications/rules/:owner`(전부) |

규칙은 내장 알림을 **대체**합니다. 즉, 확장이 `run_finished` 규칙을 등록하면 그 이벤트의 기본 알림 대신 확장의 문구로 나갑니다. → [[client-extensions]]

## 새 기기 연결 (QR)

관리자 토큰을 직접 옮기지 않고 폰·다른 PC를 연결하는 방법입니다.

::: steps
### 연결 코드 만들기

이미 연결된 PC 앱에서 **설정 → 기기 → 폰 추가**를 열고 **QR 만들기**를 누릅니다. 폰이 접속할 주소를 확인하세요. `localhost` 주소는 폰에서 폰 자신을 가리키므로 Tailscale 주소나 LAN 주소로 바꿔야 합니다.

### 스캔

새 기기에서 앱을 열고 QR을 카메라로 스캔합니다. 링크 형태는 `pipaya://connect…`이며 링크 복사로 직접 전달할 수도 있습니다.

### 서버가 기기를 등록

코드가 유효하면 서버가 **그 기기 전용 토큰**(`hdt_…`)을 만들어 돌려주고, 코드는 즉시 폐기됩니다.
:::

### 코드와 토큰의 성질

| 항목 | 값 |
|---|---|
| 코드 유효 시간 | **2분**, **1회용** |
| 동시 유효 코드 | 최대 5개 (가장 오래된 것이 밀려남) |
| 코드 형식 | 24바이트 무작위(base64url). 서버는 **SHA-256 해시만** 메모리에 보관. 재시작하면 모두 무효 |
| 잘못된 코드 | 호출자당 분당 **10회**, 전체 분당 **100회**까지. 넘으면 `429` |
| 기기 토큰 | `hdt_` + 32바이트 무작위. DB에는 **SHA-256 해시만** 저장 |
| 라벨 | 기기가 스스로 붙인 이름, 최대 60자 |
| 마지막 사용 | 60초 단위로 갱신 |

QR에는 관리자 토큰이 들어 있지 않습니다. 화면을 촬영당해도 코드는 곧 무효가 되고, 한 번 쓰면 끝입니다.

### 기기 토큰의 권한

기기 토큰은 **관리자 토큰보다 좁습니다.** 대부분의 API를 쓸 수 있지만 다음은 거부됩니다(`403 admin_only`).

- `POST`/`DELETE /pairing` — 새 기기를 열어 주는 일
- `GET /devices/tokens`, `DELETE /devices/tokens/:id` — 기기 목록·해지
- `POST /server-extensions/reload` — 서버 확장 다시 읽기(코드 실행)
- `GET`/`POST /server/update` — 서버 코드 교체와 재시작

즉 연결된 폰은 다른 폰을 추가하거나 서버 코드를 바꿀 수 없습니다.

## 기기 관리와 해지

설정 → 기기에서 이 토큰으로 접속한 기기를 봅니다.

| 표시 | 설명 |
|---|---|
| 이름, 종류 | 웹 브라우저, 데스크톱 앱, 안드로이드 등 + OS·앱 버전 |
| 연결됨 / 연결 끊김 | 지금 하트비트가 오는지. 이 기기는 "이 기기"로 표시 |
| 마지막 접속 | n초·분·시간·일 전 |
| 모바일 푸시 | 푸시 토큰이 있는지, 알림이 꺼져 있는지 |

**QR로 연결한 기기** 목록에서 기기를 **접속 취소**하면(확인 한 번 더) 그 기기의 토큰이 지워지고 열려 있던 소켓이 즉시 끊깁니다. 다른 기기와 서버 토큰은 그대로입니다. 해지된 기기는 `device_revoked` 이벤트를 받고 보고를 멈춥니다. 알림 수신 기기 목록의 해지(`DELETE /notifications/devices/:id`)는 별개로 **알림 등록만** 지웁니다.
