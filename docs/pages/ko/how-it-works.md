pipaya의 구조와 메시지 하나가 처리되는 과정을 설명합니다. 문제가 생겼을 때 어디를 봐야 하는지 알기 위한 문서입니다.

## 프로세스와 저장소

서버는 하나의 Bun 프로세스입니다. 모든 영구 데이터는 `~/.pipaya/pipaya.db`(SQLite)에 있습니다.

| 테이블 | 내용 |
|---|---|
| `sessions` | 세션 레코드(제목, 작업 폴더, 모델, 승인 정책, 닫힘 여부 등) |
| `messages` | 세션별 대화 기록. `seq` 순서 |
| `events` | 이벤트 로그. **7일** 후 만료 |
| `credentials` | 프로바이더 API 키·OAuth 자격 증명 (**암호화되지 않음**) |
| `custom_providers` | 사용자가 등록한 모델 엔드포인트 |
| `settings` | 기본 모델, 기본 폴더, 기본 승인, 압축, 하위 에이전트, 시스템 모델, 정리 정책, 스킬 켜기/끄기, 역할 등 키-값 |
| `groups` | 분할 화면 그룹 |
| `session_contexts` | 세션 첫 실행 때 고정한 AGENTS.md 스냅샷 |
| `session_compactions` | 압축 요약 |
| `session_skills` | 세션별 스킬 정보 |
| `extension_entries` | 서버 확장이 세션에 남긴 기록 |
| `device_tokens` | QR로 연결한 기기 토큰(해시만) |
| `notification_*` | 알림 기기, 규칙, 중복 방지, 지연 푸시 |
| `client_settings` | 서버에 묶인 클라이언트 설정 |

메모리에만 있는 것: 진행 중인 에이전트 루프, 스트리밍 중인 부분 메시지, **터미널**, 연결 코드(QR), 접속 중인 기기의 상태.

> [!NOTE]
> 서버를 재시작하면 진행 중이던 작업은 중단되고 자동으로 이어지지 않습니다. 대화 기록과 설정은 DB에 남아 있습니다. 터미널은 모두 종료됩니다.

## 메시지 하나의 여정

::: steps
### 요청

클라이언트가 `POST /sessions/:id/messages`로 `{text, mode?, images?, files?}`를 보냅니다. 서버는 바로 `202`를 돌려주고 작업은 백그라운드에서 진행합니다. 세션이 실행 중인데 `mode`가 `prompt`이면 `409`입니다.

### 메시지 조립

서버가 사용자 메시지를 만들 때 다음을 덧붙입니다.

- 프롬프트 템플릿(`/prompt:이름`)이면 확장한 본문과 표시용 마커
- `/subagent:이름`, `@세션`, `/skill:이름`을 쓰면 모델에게만 보이는 **숨은 안내**(`<pipaya-hint>`)
- 첨부 이미지, 그리고 파일이면 `.pipaya/uploads/`에 저장하고 경로 안내(`<pipaya-files>`)

### 자동 압축 확인

자동 압축이 켜져 있고 컨텍스트가 임계값에 닿았으면 프롬프트 전에 오래된 기록을 요약합니다. → [[context]]

### 에이전트 루프

모델을 호출하고, 모델이 도구를 요청하면 실행하고, 결과를 다시 모델에 넣는 과정(턴)을 반복합니다. 도구 호출 전에는 **승인 정책 검사**를 거칩니다. → [[tools]]

### 끝

모델이 도구 없이 답하면 실행이 끝나고 `run_finished`가 나갑니다. 대기열의 후속 메시지(`follow_up`)가 있으면 이어서 처리합니다.
:::

## 이벤트로 알리기

모든 진행 상황(메시지, 도구 실행, 승인 요청, 상태 변화)은 이벤트로 발행되어 SSE와 WebSocket으로 구독자에게 전달됩니다. 영구 이벤트는 전역 커서(`id`)를 가지고 7일 동안 저장되어, 끊겼다 다시 붙은 클라이언트가 놓친 부분을 재생해 받습니다. 스트리밍 조각(`message_update`, `tool_execution_update`)은 저장되지 않으므로 **프롬프트를 보내기 전에 먼저 구독**해야 합니다. → [[events]]

## 폭주 방지

| 장치 | 값 |
|---|---|
| 한 실행당 최대 모델 호출 | 200회 (`PIPAYA_MAX_RUN_TURNS`로 변경) |
| 같은 도구 호출 반복 | 연속 6번 같은 이름·인자의 호출이 나오면 중단 |
| 중단 요청 후 강제 종료 | 8초 안에 멈추지 않으면 실행을 끊고 `aborted`로 종료 |
| 승인 대기 | 기본 10분 후 자동 거부 |

한 번의 실행이 이 한도에서 멈추면 "메시지를 보내 이어서 진행"하라는 안내와 함께 끝납니다.

## 메모리 관리

30분 동안 쓰지 않은 세션은 메모리에서 내려가고, 다음에 쓸 때 DB에서 다시 올립니다. 기록은 사라지지 않습니다.

## 시스템 프롬프트 구성

세션의 시스템 프롬프트는 다음 순서로 합쳐집니다.

1. 기본 프롬프트 (또는 세션 생성 때 준 `systemPrompt`)
2. **AGENTS.md** — 세션 첫 실행 때 고정된 전문
3. `<available_skills>` — 현재 켜진 스킬의 이름·설명·경로
4. `# Sub-agents` — `delegate` 도구가 있는 세션에서, 켜진 하위 에이전트가 있을 때만

2번은 세션 동안 변하지 않고, 3·4번은 설정을 바꾸면 다음 메시지부터 반영됩니다. 자세한 규칙은 [[context]]를 보세요.

## 클라이언트가 하는 일

클라이언트는 서버의 REST로 상태를 읽고 SSE로 실시간 갱신을 받아 화면에 합칩니다. 서버가 저장하는 것(세션, 모델 설정, 그룹, 서브에이전트 등)과 기기에 남는 것(테마, 단축키, 알림음, 서버 목록·토큰)은 구분됩니다. → [[settings]]
