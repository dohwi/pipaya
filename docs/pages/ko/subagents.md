본 에이전트가 검색 같은 일을 **도우미**에게 맡기면, 도우미는 별도 기록에서 일하고 **짧은 보고서 하나**만 돌려줍니다. 파일 내용이 본 대화에 쌓이지 않아 컨텍스트를 아낍니다.

> [!NOTE]
> 새 서버에는 도우미가 **하나도 없습니다.** 도우미를 만들기 전에는 `delegate`가 쓰이지 않고, 시스템 프롬프트에 `# Sub-agents` 블록도 들어가지 않습니다.

## 언제 쓰나

- 코드베이스에서 정의 위치나 흐름을 찾는 **조사**
- 파일을 여러 번 읽어야 하지만 결과는 몇 줄이면 되는 일
- 값싼 모델로 충분한 탐색 작업

본 에이전트가 직접 하면 읽은 파일이 모두 대화에 남습니다. 도우미는 그 과정을 자기 기록에만 두고 요약만 돌려줍니다.

## 도우미가 할 수 있는 일과 없는 일

| | |
|---|---|
| 도구 | `read` `grep` `ls`(읽기 전용), `write` `edit` `bash`(변경)에서 고른 것 |
| 못 하는 일 | 사용자에게 질문(`ask_user`), 다른 도우미 호출(`delegate`) |
| 대화 내용 | **보지 못함.** 요청문(`task`, 최대 4,000자)에 담긴 것만 앎 |
| 결과 | 약 300단어 보고서, `경로:줄` 인용. 6,000자에서 잘림 |
| 호출당 출력 | 모델 호출마다 최대 2,048토큰 |
| 추론 강도 | 기본 `minimal` (모델 항목에서 따로 지정하지 않으면) |

보고서가 길어서 잘리면 `[report cut at the length limit]`, 단계 한도에서 멈추면 `[stopped at the N-step limit; this report may be incomplete]`가 붙습니다. 보고서는 **단서**로 보고, 인용된 줄을 직접 확인한 뒤 고치세요.

쓰기 도구(`write`, `edit`, `bash`)가 있는 도우미는 일반 도우미 프롬프트("할 일만 하고, 바꾼 파일을 모두 나열")로 동작하며, 도구 호출 전의 **승인 정책이 그대로 적용**됩니다 → [[tools]]. 서버 확장의 `tool_call` 훅도 도우미를 거치므로 정책 확장을 우회할 수 없습니다.

## 설정

설정 → 서버 → **에이전트**에서 만듭니다.

| 필드 | 규칙 |
|---|---|
| 전체 켜기 | `delegate` 도구 전체의 마스터 스위치 |
| 개수 | 최대 **10개**. 이름은 고유 |
| `name` | 소문자로 시작, 소문자·숫자·`-`, 최대 40자. 본 에이전트가 `agent`로 넘기고 사용자는 `/subagent:이름`으로 부름 |
| `description` | 1~200자. 본 에이전트가 **언제 이 도우미를 고를지** 판단하는 근거이므로 "언제 쓰는지"를 적기 |
| 켜기 | 끈 도우미는 제안되지 않음 |
| 모델 | 비우면 **호출한 대화의 모델**. 지정하면 `{provider, model, thinkingLevel?}`. 등록되지 않은 모델은 저장 거부(`400`). 나중에 모델이 삭제되면 조용히 호출한 대화의 모델로 대체 |
| `tools` | 1~6개, 중복 불가 |
| 최대 단계(`maxTurns`) | 2~30, 기본 **12**. 이만큼 모델을 부르면 멈추고 그때까지의 보고서를 줌 |
| `prompt` | 최대 2,000자. 기본 지침 **뒤에 덧붙음** |

설정은 서버(DB 키 `subagents`)에 저장되어 모든 기기가 공유합니다. 잘못된 저장은 아무것도 바꾸지 않으며 모르는 키는 거부합니다. 설정 화면의 안내: "이 횟수만큼 모델을 부르면 서브에이전트를 멈추고 그때까지의 보고서를 받습니다."

> [!WARNING]
> `PUT /subagents`는 **전부 교체**합니다. 먼저 `GET`으로 가져와 한 항목만 고친 뒤 전체를 다시 보내세요. 일부만 보내면 나머지 도우미가 지워집니다.

### 비용 줄이기

- 탐색용은 **가볍고 저렴한 모델 + `minimal` 추론**이면 대개 충분합니다. 보고서가 얕으면 모델을 올리세요.
- 모델의 연결에 키가 없으면 도우미가 실패하므로 설정 화면에 경고가 뜹니다.
- 추론을 지원하지 않는 모델은 강도 설정을 무시합니다.

## 파일로 정의하기

도우미를 Markdown 파일로 만들 수도 있습니다. 파일은 **매 턴마다 읽으므로** 고치면 다음 메시지부터 적용됩니다.

| 위치 | 범위 |
|---|---|
| `~/.agents/subagents/<이름>.md` | 전역 (서버 사용자의 홈) |
| 루트부터 작업 디렉터리까지 각 폴더의 `.agents/subagents/<이름>.md` | 프로젝트. 가까운 폴더가 이김 |

```markdown
---
name: fixer
description: 작고 분명한 버그를 고치고 테스트를 실행한다
model: openai/gpt-5-mini
thinking: low
tools: [read, grep, ls, edit, bash]
maxTurns: 20
enabled: true
---
수정할 때마다 프로젝트 테스트를 실행하고 바꾼 파일을 모두 나열하라.
```

| 필드 | 설명 |
|---|---|
| `name` | 선택. 기본은 파일 이름(`.md` 제외). 규칙은 위와 같음 |
| `description` | **필수**, 1~200자 |
| `model` | `provider/model` 형식, 또는 생략·`inherit`(= 호출한 대화의 모델) |
| `thinking` | `minimal`~`max`. `model`이 있어야 의미 있음. 기본 `minimal` |
| `tools` | 목록 또는 `read, grep` 문자열. 기본 `read, grep, ls` |
| `maxTurns` | 2~30, 기본 12 |
| `enabled` | 기본 `true` |
| 본문 | 추가 지침 (최대 2,000자) |

- `*.md`만, **32KB 이하**만 읽습니다. 잘못된 파일은 경고와 함께 건너뜁니다.
- **같은 이름이면** 파일이 서버에 저장된 도우미를 대체하고, 가까운 파일이 먼 파일을 대체합니다.
- 파일에 적은 모델은 쓸 때 확인하지 않습니다. 없는 모델이면 도우미는 호출한 대화의 모델로 실행됩니다.
- 파일 도우미는 본 에이전트의 도우미 목록과 `delegate` 설명에 나오지만, 지금은 설정 화면에는 나오지 않습니다.

## 부르는 방법

| 방법 | 동작 |
|---|---|
| 자동 | 본 에이전트가 도우미의 설명을 보고 필요할 때 `delegate`를 호출. `agent`를 생략하면 켜진 첫 도우미 |
| 수동 | 입력창에 `/subagent:이름`. 해당 도우미를 쓰라는 **숨은 안내**가 붙음 (강한 힌트일 뿐 보장은 아님) |

`/subagent:이름`은 줄 시작이나 공백 뒤에 쓰고, **현재 켜져 있는** 도우미 이름만 인정됩니다. `/` 메뉴에 **서브에이전트** 태그로 나옵니다.

## 좋은 도우미 설계

- 도우미 하나는 **한 가지 일**만. 이름도 일에 맞게(`explore`, `tests-finder`, `api-routes`).
- `description`에 호출 조건을 적기: "정의 위치나 흐름을 찾을 때 쓴다".
- `prompt`에는 출력 형식, 건너뛸 폴더 같은 **사내 규칙**을 적기.
- 권한은 `tools`로 정합니다. `write`·`edit`·`bash`는 정말 필요한 도우미에만 주세요.

## 세션 협업과의 차이

임시 도우미는 보고서 하나를 돌려주고 끝납니다. 독립적으로 오래 일하는 다른 대화와 협업하려면 [[orchestration]]을 보세요.

## 에이전트에게 맡기기

내장 스킬 `pipaya-usage`가 있어서 "저장소 구조를 조사하는 하위 에이전트를 추가해줘"처럼 말하면 에이전트가 API나 파일로 만들어 줍니다. 기본은 읽기 전용 도구(`read`, `grep`, `ls`)이며 변경 도구는 요청할 때만 줍니다.
