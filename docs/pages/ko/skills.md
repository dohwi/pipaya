스킬은 **필요할 때만 읽는 지식과 절차**입니다. [Agent Skills](https://agentskills.io/specification) 형식(`<이름>/SKILL.md`)을 따릅니다.

## 동작 방식

[[agents-md]]는 전문이 항상 시스템 프롬프트에 들어가지만, 스킬은 **이름·설명·경로만** `<available_skills>` 블록으로 들어갑니다. 모델은 지금 하는 일에 맞는다고 판단하면 `read`로 `SKILL.md`를 열어 따릅니다. 그래서 컨텍스트를 아끼면서 긴 절차를 쓸 수 있습니다.

> [!TIP]
> **설명이 곧 호출 조건입니다.** 스킬이 쓰이는지는 `description`에 달려 있으니 "언제 읽어야 하는지"를 구체적으로 적으세요.

## 만들기

```markdown
---
name: release-notes
description: 릴리스 노트를 쓰거나 CHANGELOG를 갱신할 때 읽는다. 커밋 로그를 요약하는 절차와 형식을 담고 있다.
---

# 릴리스 노트 작성

1. `git log --oneline <이전 태그>..HEAD`로 변경을 모은다.
2. 사용자에게 보이는 변경만 골라 "추가 / 변경 / 수정"으로 나눈다.
3. ...
```

| 규칙 | 값 |
|---|---|
| 파일 | `<스킬 폴더>/SKILL.md` |
| `name` | 소문자·숫자·단일 하이픈(`my-skill`), 최대 64자. 비우면 폴더 이름 |
| `description` | 최대 1,024자. 넘으면 잘라서 쓰고 경고 |
| 폴더 이름 | `name`과 같게 맞추기를 권장 (Agent Skills 규격) |
| 개수 | 발견되는 스킬은 최대 200개 |
| 탐색 깊이 | 스킬 폴더 안으로 최대 4단계 |

이름이나 형식이 잘못된 파일은 경고와 함께 건너뛰고 나머지는 정상 처리합니다. 경고는 `GET /skills`의 `warnings`와 스킬 창 맨 위에 보입니다.

## 위치와 우선순위

| 출처 | 위치 |
|---|---|
| 프로젝트 | 작업 디렉터리에서 git 루트(저장소가 없으면 `/`)까지의 `.pi/skills/`와 `.agents/skills/` |
| 전역 | 서버 사용자의 `~/.agents/skills/` |
| 내장 | 서버의 `builtin-skills/`. 모든 프로젝트에서 켜져 있고 다른 스킬처럼 끌 수 있음 |

이름이 겹치면 **가까운 폴더 > 프로젝트 > 전역 > 내장** 순으로 이깁니다. 내장 스킬을 같은 이름으로 덮어써도 알림은 없습니다.

내장 스킬:

| 이름 | 용도 |
|---|---|
| `pipaya-usage` | pipaya 자신의 설정(하위 에이전트, AGENTS.md, 스킬 켜기/끄기)을 에이전트가 다루게 함 |
| `pipaya-client-extensions` | 클라이언트 확장 시스템 설명과 작성 참고 자료 |
| `pipaya-server-extensions` | 서버 확장 작성 참고 자료 |

내장 스킬을 추가하려면 저장소의 `server/builtin-skills/<이름>/SKILL.md`를 만듭니다(Docker 이미지가 이 폴더를 복사).

## 켜기와 끄기

스킬 창은 입력창 아래의 책 아이콘, 또는 *스킬 열기* 단축키로 엽니다.

| 범위 | 설명 |
|---|---|
| **전역** | 모든 프로젝트의 기본값 |
| **프로젝트** | git 루트별 재정의. 전역 기본과 같게 되돌리면 기본을 따름 (`enabled: null`) |

실제 상태 = **프로젝트 값이 있으면 그것, 없으면 전역 값**. 기본은 모두 켜짐입니다. 상태는 스킬 폴더가 아니라 서버 DB(`settings.skills`)에 저장되어 같은 서버의 모든 기기가 공유합니다.

- 끄면 목록에서 빠지고 **그 폴더를 읽는 것도 막힙니다.** 이미 읽은 내용은 기록에 남습니다.
- 변경은 **다음 메시지부터** 현재 설정이 적용됩니다. 켜진 목록이 실제로 바뀐 경우에만 맨 앞 시스템 메시지를 다시 쓰므로 프롬프트 캐시가 유지됩니다.
- `read` 도구가 없는 세션에는 스킬을 안내하지 않습니다.
- 변경은 `skills_updated` 이벤트로 열린 앱에 알려집니다.

API: `GET /skills?cwd=&sessionId=`, `PUT /skills/:name` `{scope: "global" | "project" | "session", enabled: true | false | null, cwd?, sessionId?}`. `session` 범위에는 `sessionId`가 필요합니다. 응답의 각 스킬에는 `globalEnabled`, `override`(프로젝트), `sessionOverride`, 최종 `enabled`가 들어 있습니다.

## 수동 호출

메시지에 `/skill:이름`을 쓰면 서버가 그 스킬의 `SKILL.md` 전문을 숨은 안내로 함께 보냅니다. 모델이 알아서 읽기를 기다리지 않고 **지금 확실히 쓰게** 할 때 씁니다. `/` 메뉴에 **스킬** 태그로 나옵니다.

```text
/skill:release-notes 이번 버전 노트 써줘
```

- 켜져 있는 스킬만 호출됩니다. 없거나 꺼진 이름은 일반 글자입니다.
- 이름 앞은 줄 시작 또는 공백이어야 하고, 뒤는 끝·공백·`. , ; : ! ? )`여야 합니다.

### 수동 전용 스킬

프론트매터에 `disable-model-invocation: true`를 넣으면 모델의 `<available_skills>` 목록에는 **들어가지 않고**, 스킬 창에는 "수동 전용"으로 보입니다. `/skill:이름`으로만 쓸 수 있고, 켜고 끌 수는 없습니다.

## 스킬이 읽을 수 있는 범위

`read` 도구는 보통 작업 폴더 기준으로 동작하지만, **켜진 스킬 폴더 안의 파일**은 작업 디렉터리 밖에 있어도 읽을 수 있도록 허용됩니다(심볼릭 링크로 폴더 밖을 가리키는 파일은 거부). 스킬 폴더에 참고 자료(`references/`)를 두고 `SKILL.md`에서 안내하면 됩니다.

## 스킬 vs 다른 수단

| 이럴 때 | 쓸 것 |
|---|---|
| 항상 지켜야 하는 짧은 규칙 | [[agents-md]] |
| 특정 작업의 긴 절차·참고 자료 | **스킬** |
| 같은 요청을 자주 반복 | [[templates]] |
| 파일을 많이 읽는 조사 | [[subagents]] |
| 새 도구나 `/명령` | [[server-extensions]] |
