여러 대화(세션)를 띄워 두고, 한 세션이 다른 세션에 일을 맡기거나 진행 상황을 읽게 하는 기능입니다. 입력창에서 `@이름`으로 지목합니다.

## 개념

| 용어 | 설명 |
|---|---|
| 세션 | 대화 하나. 각자 모델, 작업 폴더, 기록이 독립적 |
| 이름 (`@이름`) | 세션마다 자동으로 붙는 호출명 |
| 역할 (`purpose`) | 이 세션이 맡은 일 한 줄. 시스템 모델이 작성 → [[models]] |
| 창 (pane) | 화면에 보이는 세션. 분할 화면은 여러 창을 동시에 보여 줌 → [[panes]] |
| 협업 도구 | `peer_send`(보내기), `peer_read`(읽기) |

세션은 **서로의 대화를 자동으로 공유하지 않습니다.** 보낸 메시지에 적힌 내용만 상대에게 전달됩니다.

## 세션 이름

새 세션이 만들어질 때, 활성 세션이 쓰지 않는 이름 중 아래 순서의 첫 번째가 배정됩니다.

```text
철수, 미나, 제임스, 영희, 민준, 소피아, 지우, 에밀리, 하준, 루카, 서연, 토마스
```

- 12개를 모두 쓰고 있으면 `철수2`, `철수3`… 으로 이어집니다.
- 이름은 **활성 세션 기준**이며 대소문자를 구분하지 않습니다.
- 닫은 세션은 `@` 목록에서 빠지고 이름도 다시 쓸 수 있습니다.
- 사이드바와 창 제목 줄에 `@이름`이 표시되고, 제목은 첫 메시지로 자동 정해지거나 `/rename`으로 바꿉니다. 메뉴에는 이름과 함께 **창 제목**이 보여서 무슨 일을 하는 세션인지 알아볼 수 있습니다.

## 사용법

### 일 맡기기

```text
@미나 에게 로그인 API 테스트를 작성하라고 시켜줘
```

1. 입력창에 `@`를 입력하고 목록에서 세션을 고릅니다.
2. 요청을 보냅니다.
3. 지금 대화의 에이전트가 `peer_send`로 미나에게 작업을 전달합니다.
4. 미나는 자기 세션에서 **독립적으로** 일합니다.

### 결과 확인하기

```text
@미나 가 어디까지 했는지 확인하고 요약해줘
```

에이전트가 `peer_read`로 미나의 최근 기록을 읽고 요약합니다.

### 여러 세션 한꺼번에

```text
@철수 는 서버 쪽, @미나 는 클라이언트 쪽을 맡아. 인터페이스는 docs/api.md 기준이야
```

한 메시지에 여러 이름을 쓸 수 있고, 같은 이름을 반복해도 한 번만 인식됩니다.

## 내부 동작

::: steps
### 숨은 안내 덧붙임

메시지에 `@이름`이 있으면 서버가 에이전트에게 **숨은 안내**를 덧붙입니다. "사용자가 이 세션들을 지목했으니 `peer_send`로 일을 맡기고 `peer_read`로 확인하라. 그들이 한 일을 추측하지 마라"는 내용이며 화면에는 보이지 않습니다.

### 전달

에이전트가 `peer_send(to, message)`를 호출합니다. 받는 세션에는 아래 머리말이 붙은 메시지가 도착합니다.

```text
[from @보낸이, another session on this server; answer with peer_send to @보낸이 only if a reply is needed]
```

### 받는 쪽의 처리

받는 세션이 **대기 중이면** 새 요청으로 시작합니다. **작업 중이면** 후속 요청(`follow_up`)으로 대기열에 들어가 현재 턴이 끝난 뒤 처리됩니다.

### 보낸 쪽은 기다리지 않음

보낸 쪽은 바로 이어서 진행합니다. 결과가 필요하면 나중에 `peer_read`로 확인하거나 받는 쪽에 답장을 요청해야 합니다.
:::

## 도구 규격

| 도구 | 인자 | 제한 |
|---|---|---|
| `peer_send` | `to`(이름, `@`는 생략 가능), `message` | 이름 1~60자, 메시지 1~8,000자. **한 실행당 최대 10번** |
| `peer_read` | `from`, `count`(선택) | `count` 1~40, 기본 10. 메시지당 앞 1,500자만 반환 |

- 두 도구는 **모든 세션에 기본으로 들어가고** 승인 요청 없이 실행됩니다.
- `peer_read`는 텍스트와 도구 호출 이름(`[tool bash]` 형태)만 보여 줍니다. 도구 출력 본문, 이미지, 숨은 안내는 포함되지 않습니다.
- 상대가 아직 작업 중이면 결과 맨 앞에 "still working" 안내가 붙습니다. 기록이 없으면 `has no messages yet`이 돌아옵니다.
- 모르는 이름이면 오류와 함께 **지금 부를 수 있는 세션 목록**이 돌아옵니다. 대소문자는 무시합니다.
- 자기 자신에게는 보낼 수 없고, 닫힌 세션은 찾을 수 없습니다.

## 무한 핑퐁 방지

두 세션이 서로에게 계속 답장하면 끝나지 않을 수 있어서, 한 세션은 **한 번의 실행 중 `peer_send`를 10번까지만** 할 수 있습니다. 11번째부터는 "중단하고 사용자에게 보고하라"는 오류(`409`)가 에이전트에게 돌아갑니다.

권장 습관:

- 답장이 꼭 필요할 때만 "끝나면 알려줘"라고 명시하세요. 받는 세션도 머리말에서 "필요할 때만 답하라"고 안내받습니다.
- 한 세션이 전체를 조율하는 **허브 구조**로 두고, 나머지는 허브에만 보고하게 하면 흐름이 단순합니다.

## 권한과 안전

- 협업 도구 자체는 승인이 필요 없지만 **받는 세션은 자기 승인 정책**으로 동작합니다. 받는 세션이 파일을 쓰거나 명령을 실행하려 하면 그 세션에서 승인 요청이 뜹니다.
- 받는 세션의 작업 폴더가 다르면 그 폴더 기준으로 일합니다. 둘 이상의 세션이 같은 폴더를 동시에 고치면 **서로의 변경을 덮어쓸 수 있으니** 폴더·파일 단위로 역할을 나누세요.
- `auto` 정책 세션에 일을 맡기면 확인 없이 실행됩니다. 격리된 환경에서만 쓰세요 → [[security]].

## 하위 에이전트와의 차이

| | **하위 에이전트** (`delegate`) | **세션 협업** (`@`, `peer_send`) |
|---|---|---|
| 상대 | 일시적인 도우미 | 독립된 대화(세션) |
| 맥락 | 요청문만 봄 | 자기 기록과 작업 폴더가 있음 |
| 결과 | 보고서 1건이 바로 돌아옴 | 비동기. 나중에 `peer_read`로 확인 |
| 도구 | 설정한 도구만 (기본 읽기 전용) | 그 세션의 모든 도구와 승인 정책 |
| 모델 | 도우미별 지정 가능 | 세션이 쓰는 모델 |
| 용도 | 검색·조사처럼 짧고 읽기 위주 | 길게 이어지는 병렬 작업, 역할 분담 |

## 활용 예시

**역할 분담**

```text
@철수 는 백엔드, @미나 는 프런트. 철수가 API 명세를 docs/api.md에 쓰면 미나가 그걸 읽고 구현하게 해줘
```

**리뷰어 세션**

```text
@제임스 는 리뷰 전용 세션이야. 내 변경이 끝나면 diff를 보내서 리뷰 받고 지적 사항을 요약해줘
```

**진행 점검**

```text
@철수 @미나 둘 다 지금 어디까지 했는지 읽어서 표로 정리해줘
```

## 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| `@` 메뉴에 세션이 없음 | 이름 있는 다른 활성 세션이 없음. 새 대화를 열기 |
| "session @이름 …" 찾을 수 없음 | 닫힌 세션이거나 이름 오타. 오류에 표시되는 목록에서 고르기 |
| 10번 제한 오류 | 핑퐁 방지 장치. 요약 보고를 요청하고 새 지시로 이어가기 |
| 상대가 반응하지 않음 | 작업 중이면 대기열에서 순서를 기다림. `peer_read`로 상태 확인 |
| 상대가 멈춰 있음 | 그 세션에서 승인 요청이 대기 중일 수 있음. 사이드바에 승인 대기 상태가 표시됨 |
| 서로 파일을 덮어씀 | 같은 폴더를 동시에 수정함. 폴더·파일 단위로 역할 분담 |
