모델이 실제로 보는 것(컨텍스트)이 어떻게 만들어지는지, 그것을 어떻게 확인하는지, 길어지면 어떻게 줄이는지를 설명합니다.

## 모델이 보는 것

세션의 컨텍스트는 크게 둘입니다.

| 구분 | 내용 | 변하는 시점 |
|---|---|---|
| 시스템 프롬프트 | 기본 프롬프트 + AGENTS.md + 스킬 목록 + 하위 에이전트 목록 | 아래 표 참고 |
| 대화 기록 | 사용자·어시스턴트·도구 결과 메시지 (압축되면 요약 + 최근 부분) | 매 턴 |

### 시스템 프롬프트 구성

| 순서 | 블록 | 내용 | 반영 시점 |
|---|---|---|---|
| 1 | 기본 프롬프트 | 샌드박스된 작업 폴더 안에서 도구로 작은 단계씩 검증하며 일하는 코딩 어시스턴트. 상대 경로를 쓰고, 첨부·결과 파일은 작업 폴더 안에서 마크다운 링크로 알림 | 세션 생성 때 `systemPrompt`로 바꿀 수 있음 (첫 메시지 후 고정) |
| 2 | AGENTS.md | 전역·상위 폴더·작업 폴더의 규칙 전문 | **세션 첫 실행 때 고정** |
| 3 | `<available_skills>` | 켜진 스킬의 이름·설명·경로 | 다음 메시지부터. 켜진 목록이 바뀔 때만 맨 앞 시스템 메시지를 다시 씀 |
| 4 | `# Sub-agents` | 켜진 하위 에이전트의 이름·설명 | 다음 메시지부터. `delegate` 도구가 있고 켜진 도우미가 있을 때만 |

3번과 4번은 해당하는 것이 없으면 블록 자체를 넣지 않습니다. 스킬 목록은 `read` 도구가 없는 세션에는 안내하지 않습니다.

시스템 메시지는 켜진 목록이 실제로 바뀐 경우에만 다시 쓰므로, 그 밖의 설정 변경은 프로바이더의 **프롬프트 캐시**를 깨뜨리지 않습니다.

### 숨은 안내

사용자 메시지에는 화면에 보이지 않는 안내 블록이 덧붙을 수 있습니다. 모두 `<pipaya-hint>`로 시작하고 모델에게만 전달됩니다.

| 계기 | 덧붙는 내용 |
|---|---|
| `/subagent:이름` | 그 도우미를 쓰라는 안내 |
| `@세션이름` | 지목한 세션을 `peer_send`/`peer_read`로 다루라는 안내 |
| `/skill:이름` | 그 스킬의 `SKILL.md` 전문 |

프롬프트 템플릿(`/prompt:이름`)은 확장한 본문이 사용자 메시지 자체가 되고, 짧은 호출문은 말풍선 아래 메모로 보입니다. 첨부 파일은 저장 경로·형식·크기 안내(`<pipaya-files>`)가 붙습니다.

## 컨텍스트 확인

대화 헤더의 **세션 컨텍스트**(또는 `GET /sessions/:id/context`)에서 확인합니다.

| 항목 | 설명 |
|---|---|
| 적용된 AGENTS.md | 파일 경로, 범위(`global` / `ancestor` / `cwd`), 바이트 수, 경고 |
| 활성 스킬 | 지금 이 세션에서 보이는 스킬 |
| 시스템 프롬프트 | 실제 전문 (`effectiveSystemPrompt`) |
| `skillsPrompt`, `agentsPrompt` | 4번·3번 블록의 정확한 텍스트 |
| 도구 | 활성 도구 목록 |
| 이미 읽은 파일 | 이 세션에서 읽은 파일 |

에이전트가 왜 그렇게 행동하는지 모르겠다면 가장 먼저 여기를 보세요.

상태줄에는 이 정보가 요약되어 나옵니다: 적용된 AGENTS.md 개수, 사용 가능한 스킬·템플릿 개수(눌러서 목록 보기), 현재 컨텍스트 사용량.

## 컨텍스트 사용량 표시

| 표시 | 의미 |
|---|---|
| 컨텍스트 `사용 / 윈도우` | **마지막 모델 호출** 기준. 새 입력과 도구 결과는 포함되지 않음 |
| `~` 접두 | 이전 버전 서버의 추정치 |
| `—` | 압축 직후라 아직 측정하지 못함 |
| 캐시 적중률 | 프롬프트 토큰 중 캐시에서 읽은 비율 |
| 출력 속도 | 마지막 응답의 토큰/초(tps) |
| 누적 비용 | 이 대화의 비용과 모델 호출 횟수 |

**현재 컨텍스트**와 **누적 과금 토큰**은 다릅니다. 누적은 호출마다 입력이 반복해서 더해지므로 컨텍스트보다 훨씬 커집니다. 사용량은 `input`, `output`, `cacheRead`, `cacheWrite`, `totalTokens`, `cost`(USD), `turns`로 집계됩니다.

## 압축

오래된 기록을 요약해서 모델이 **요약을 대신 보게** 하는 기능입니다. 저장된 원본 기록은 그대로 남습니다.

### 실행 방법

| 방법 | 설명 |
|---|---|
| 수동 | `/compact [지침]` 또는 `POST /sessions/:id/compact`. 지침은 최대 2,000자 |
| 자동 | 설정 → 모델 연결 → 압축의 **자동 압축**. 켜져 있으면 프롬프트를 보내기 **전에** 검사 |

### 자동 압축 조건

컨텍스트 토큰이 다음 임계값에 닿으면 실행합니다.

```text
임계값 = max( 컨텍스트 윈도우 × 0.5 , 컨텍스트 윈도우 − 16,384 )
```

즉 윈도우의 절반과 "윈도우에서 16,384토큰을 뺀 값" 중 **큰 쪽**입니다. 윈도우가 크면 뒤쪽 값이, 작으면 절반이 기준이 됩니다.

### 무엇을 요약하고 무엇을 남기나

- 최근 약 **20,000토큰** 분량은 원문 그대로 남깁니다. 잘라 내는 지점은 항상 사용자 메시지 앞입니다.
- 그보다 앞의 모든 메시지를 요약합니다. 요약은 사용자 목표·제약, 결정과 이유, 읽거나 바꾼 파일 경로, 명령과 결과, 오류와 해결, 남은 일을 사실 위주로 압축하고 인사말·반복은 버립니다.
- 요약에 넣을 도구 출력은 메시지당 2,000자로 잘립니다.
- 요약은 `session_compactions` 테이블에 저장되고, 이후 컨텍스트는 `[요약 메시지, …남긴 메시지]`로 다시 만들어집니다. 요약은 모델에게 합성 사용자 메시지로 보입니다.

### 요약 모델

설정한 **압축 모델**이 있고 사용할 수 있으면 그것을, 아니면 세션의 모델을 씁니다. 가볍고 저렴한 모델을 권장합니다. 압축 모델의 연결에 키가 없으면 압축이 실패합니다.

### 실패와 오류 코드

| 코드 | 원인 |
|---|---|
| `409` | 닫힌 세션 / 이미 압축 중 / 실행 중(수동 압축) / 승인·질문 대기 중 / 압축할 기록이 너무 짧음 / 확장이 취소 / 중단됨 |
| `501` | 이 서버에 압축 기능이 없음 (`compaction_not_supported`) |
| `502` | 요약 모델 호출 실패 (`upstream_error`) |

실패하거나 중단되면 `compaction_failed` 이벤트가 나가고 **컨텍스트는 그대로**입니다. 압축 중에는 메시지 전송과 모델 변경이 막히고, 중지 버튼으로 취소를 요청할 수 있습니다.

> [!NOTE]
> 압축은 요약 모델 호출 비용이 들고, 요약 과정에서 세부 내용이 빠질 수 있습니다.

이벤트는 `compaction_started` → `compaction_finished` 또는 `compaction_failed`입니다. 서버 확장은 `session_before_compact` 훅으로 압축을 취소하거나 요약을 직접 줄 수 있습니다 → [[server-extensions]].

## 컨텍스트를 아끼는 방법

| 방법 | 효과 |
|---|---|
| `/compact` | 오래된 기록을 요약으로 대체 |
| [[subagents]] | 파일을 여러 번 읽는 조사를 맡기고 짧은 보고서만 받음 — 읽은 내용이 본 대화에 쌓이지 않음 |
| `#` 로 경로만 알려 주기 | 파일 전체를 붙여넣는 대신 필요한 부분만 `read`로 읽게 함 |
| [[skills]] | 긴 절차를 필요할 때만 읽게 함 (AGENTS.md는 항상 들어감) |
| `/fork` | 지금까지의 내용을 복사해 새 방향으로 시도 |
