`AGENTS.md`는 에이전트에게 **항상 적용할 규칙**을 적는 파일입니다. 내용 **전문이 시스템 프롬프트에 들어갑니다.**

## 스킬·템플릿과의 차이

| | AGENTS.md | [[skills]] | [[templates]] |
|---|---|---|---|
| 모델이 보는 것 | **전문** (항상) | 이름·설명·경로만. 필요할 때 `read`로 엶 | 호출할 때만 확장된 본문 |
| 변경 반영 | **세션 첫 실행 때 고정** | **다음 메시지부터** | 즉시 |
| 용도 | 항상 지켜야 할 규칙, 환경 사실 | 특정 상황의 절차·지식 | 자주 쓰는 긴 요청 |

## 읽는 순서

시스템 프롬프트에는 아래 순서로 이어 붙습니다.

1. **전역** — `~/.agents/AGENTS.md` (서버를 실행하는 사용자의 홈)
2. **상위 폴더** — 파일시스템 루트부터 작업 디렉터리 **직전**까지 각 폴더의 `AGENTS.md`
3. **작업 디렉터리** — 그 폴더의 `AGENTS.md`

## 규칙

| 항목 | 값 |
|---|---|
| 하위 폴더 | **검색하지 않음** |
| 같은 실제 파일 | 심볼릭 링크를 풀어서 한 번만 포함 |
| 빈 파일 | 건너뜀 |
| 일반 파일이 아닌 것 | 경고와 함께 건너뜀 |
| 파일당 상한 | **64KiB** |
| 합계 상한 | **256KiB** |
| 상한 초과 | 잘라 넣지 않고 **그 파일을 통째로 제외**(경고) |

## 고정 시점

세션의 **첫 실행 때 스냅샷**이 DB(`session_contexts`)에 저장되고 이후 바뀌지 않습니다. 파일을 고쳐도 열려 있는 세션에는 반영되지 않으니 **새 대화**에서 확인하세요. 첫 메시지를 보내기 전에는 클라이언트가 지금 적용될 목록을 **미리보기**로 보여 줍니다.

## 적용 확인

대화 헤더의 **세션 컨텍스트**(파일 아이콘)에서 적용된 파일과 범위(`global` / `ancestor` / `cwd`), 바이트 수, 경고, 실제 시스템 프롬프트를 볼 수 있습니다. 상태줄의 `AGENTS.md N개`를 눌러도 같은 화면이 열립니다 → [[context]].

## 하위 에이전트와 AGENTS.md

하위 에이전트는 AGENTS.md를 받지 **않습니다.** 하위 에이전트의 프롬프트는 기본 조사 지침에 그 도우미의 `prompt` 필드를 덧붙인 것입니다 → [[subagents]].

## 쓰는 법

```markdown
# 규칙

## 환경
- Ubuntu 24.04. 패키지 설치는 `mise`를 쓴다.

## 코드
- 변경 후 `bun run typecheck && bun test`를 실행한다.
- 비밀값(`.env`, 토큰)은 읽거나 출력하지 않는다.
```

- 짧고 명령형으로, **환경 사실·꼭 지킬 규칙·자주 쓰는 명령**만 적습니다.
- 비밀값은 넣지 않습니다.
- 모노레포의 하위 폴더 규칙은 그 하위 폴더의 파일에 적습니다. 세션의 작업 디렉터리가 그 폴더일 때만(또는 부모에 적어야) 적용됩니다.
- 전역 파일을 만들기 전에 **기존 내용을 읽고 이어서 고치세요.** 덮어쓰면 환경 규칙이 사라질 수 있습니다.
- 서버가 Docker 안에 있으면 "홈"은 **컨테이너 사용자의 홈**입니다. 호스트의 `~/.agents`가 아닙니다.

## 변경 감지

서버는 `~/.agents`와, 알려진 작업 디렉터리부터 저장소 루트까지의 `.agents`, `.pi` 폴더를 감시합니다. 파일이 바뀌면 `skills_updated` 이벤트를 보내 열려 있는 앱이 스킬·템플릿·상태줄 개수를 **새로고침 없이** 다시 읽습니다. 감시할 폴더 목록은 15초마다 다시 계산하므로 나중에 만든 폴더도 잡힙니다. 단, AGENTS.md 자체는 위의 이유로 기존 세션에 반영되지 않습니다.

## 에이전트에게 맡기기

내장 스킬 `pipaya-usage`가 있어서 대화에서 "전역 AGENTS.md에 이 규칙 추가해줘"라고 하면 에이전트가 위 규칙을 지켜 처리합니다. 이때 에이전트는 서버 사용자의 홈을 먼저 확인하고, 있는 파일은 읽은 뒤 고칩니다.
