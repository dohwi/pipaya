에이전트는 도구로 실제 작업을 합니다. 이 문서는 도구 10가지의 동작, 승인 정책, 경로 규칙, 안전장치를 정리합니다.

## 도구 목록

| 도구 | 기능 | 변경 작업 | 기본 포함 |
|---|---|---|---|
| `read` | 텍스트 파일 읽기 | 아니오 | 예 |
| `write` | 파일 쓰기(덮어쓰기) | **예** | 예 |
| `edit` | 파일의 일부 교체 | **예** | 예 |
| `ls` | 폴더 목록 | 아니오 | 예 |
| `grep` | 내용 검색 | 아니오 | 예 |
| `bash` | 셸 명령 실행 | **예** | 예 |
| `ask_user` | 진행 중 사용자에게 질문 | 아니오 | 예 (설정에서 끌 수 있음) |
| `delegate` | 하위 에이전트에 조사 위임 | 도우미 도구에 따름 | 예 |
| `peer_send` | 다른 세션에 메시지 보내기 | 아니오 | **항상** |
| `peer_read` | 다른 세션의 최근 기록 읽기 | 아니오 | **항상** |

`peer_send`와 `peer_read`는 세션의 도구 목록과 상관없이 모든 세션에 들어가며 승인 없이 실행됩니다. 도구 목록과 기본값은 `GET /tools`로 볼 수 있습니다. 확장이 도구를 추가하거나 기본 목록을 바꿀 수 있습니다 → [[server-extensions]].

## 출력 제한

| 항목 | 값 |
|---|---|
| 도구 출력 상한 | **50KB**. 넘으면 **뒤쪽을 남기고** 앞에 `[output truncated, showing last 51200 bytes]`를 붙임 |
| `read` 줄 수 | 최대 **2,000줄**. 더 있으면 `[N more lines; continue with offset=…]` 안내 |
| `grep` 결과 | 최대 **200줄**. 더 있으면 `[N more matches]` |
| `grep` 시간 | 30초 |

## 각 도구

### read

| 인자 | 설명 |
|---|---|
| `path` | 파일 경로. 작업 폴더 기준 상대 경로 또는 절대 경로 |
| `offset` | 시작 줄(1부터). 기본 1 |
| `limit` | 줄 수. 기본·최대 2,000 |

파일을 UTF-8 텍스트로 읽습니다. 이미지·바이너리를 위한 별도 처리는 찾지 못했습니다. 켜져 있는 스킬 폴더는 작업 디렉터리 밖이어도 읽을 수 있습니다.

### write

`path`와 `content`를 받아 파일을 만듭니다. **상위 폴더가 없으면 만들고, 있는 파일은 덮어씁니다.**

### edit

`path`, `oldText`, `newText`. `oldText`가 파일에서 **정확히 한 번** 나와야 합니다. 없으면 `oldText was not found in the file`, 두 번 이상이면 `oldText matches more than once; include more surrounding context` 오류가 납니다. 한 번 호출에 한 곳만 바꿉니다.

### ls

`path`(기본 `.`). 폴더는 이름 뒤에 `/`가 붙고 정렬되어 나옵니다. 비어 있으면 `(empty)`. 항목 수 제한은 찾지 못했습니다.

### grep

`pattern`, `path`(선택), `glob`(선택). `rg`(ripgrep)가 설치돼 있으면 `rg -n --no-heading --max-columns 300`을, 없으면 시스템 `grep -rnIE`를 씁니다.

### bash

| 인자 | 설명 |
|---|---|
| `command` | 실행할 명령 |
| `timeout` | 초 단위 제한. 1~1800, 기본 **120** |

- 작업 디렉터리에서 `bash -c`로 실행합니다. Linux·macOS에서는 `setsid`로 새 프로세스 그룹을 만들고, 입력은 비어 있습니다(`stdin` 없음).
- 시간 초과나 중단이면 프로세스 그룹 전체에 `SIGKILL`을 보내고, 출력 파이프를 비우는 데 2초까지 기다립니다.
- **샌드박스가 아닙니다.** 서버를 실행하는 사용자 권한으로 돕니다.
- 자식 프로세스는 **허용 목록에 있는 환경 변수만** 받습니다 (`PATH` `HOME` `USER` `SHELL` `TERM` `LANG` `TZ` `TMPDIR`, 프록시 변수, `SSL_CERT_*`, `BUN_INSTALL` `CARGO_HOME` `GOPATH` `JAVA_HOME` 등, 접두어 `LC_` `XDG_` `MISE_`). `PIPAYA_*`는 하나도 전달되지 않으며, 추가로 넘기려면 서버에 `PIPAYA_BASH_ENV=NAME1,NAME2`를 지정합니다. 클라우드 자격 증명이나 FCM 서비스 계정 경로가 새지 않게 하려는 장치입니다.

### ask_user

에이전트가 진행 중에 사용자에게 묻고 답을 기다립니다.

| 인자 | 설명 |
|---|---|
| `question` | 질문. 1~2,000자 |
| `options` | 선택지. 2~8개, 각 1~200자 |
| `recommended` | 추천 선택지. `options` 중 하나 |
| `allowFreeText` | 직접 입력 허용. 기본 `true` |
| `questions` | 여러 질문을 한 번에. 2~8개 (탭으로 보이고 답을 고쳐 보낼 수 있음) |

**시간 제한이 없습니다.** 답하거나 중단할 때까지 기다립니다. 설정 → 일반의 **질문 허용**을 끄면 에이전트는 묻지 않고 가정하고 진행합니다(서버에 저장되어 모든 대화에 적용). 대기 중인 질문은 `GET /questions`로 보고 `POST /sessions/:id/questions/:toolCallId`로 답합니다.

### delegate

`task`(1~4,000자), `agent`(선택, 생략하면 켜진 첫 도우미). 도우미 구성과 제한은 [[subagents]]에 있습니다.

### peer_send / peer_read

세션 간 협업 도구입니다. → [[orchestration]]

## 승인 정책

`write`, `edit`, `bash`, 그리고 쓰기 권한이 있는 도우미를 부르는 `delegate`가 승인 대상입니다.

| 정책 | 동작 |
|---|---|
| `ask` (기본) | 프로젝트 **밖**에 닿는 변경 작업만 사용자에게 확인 |
| `auto` | 묻지 않고 실행 |
| `readonly` | 변경 작업을 차단. 모델에는 `"<tool>" is disabled: this session is read-only`가 전달됨 |

정책은 서버 기본값(`PIPAYA_APPROVAL`, 설정 → 일반의 **도구 승인**)이 있고, 새 세션은 이를 따르며 세션마다 바꿀 수 있습니다. 앱은 `ask`와 `auto`만 고르게 하고, `readonly`는 API로만 지정합니다.

### 무엇이 "프로젝트 밖"인가

`ask`에서 확인 대상인지 판단하는 규칙입니다.

| 도구 | 확인이 필요한 경우 |
|---|---|
| `write`, `edit` | 대상 경로가 작업 디렉터리 **밖**일 때 (심볼릭 링크는 실제 위치로 판단) |
| `bash` | 명령에 나온 단어 중 하나가 작업 디렉터리 밖을 가리킬 때 |
| `delegate` | 쓰기 도구가 있는 도우미는 미리 판단할 수 없어 **항상** 확인 |
| 확장이 만든 변경 도구 | 서버가 판단할 수 없으므로 **항상** 확인 |

`bash` 판단은 **문자열을 읽는 방식**이라 보수적이고 한계가 있습니다.

- 밖으로 치는 것: 작업 폴더 밖으로 풀리는 절대 경로, `~`, `$HOME`, `..`가 든 경로, 해석할 수 없는 `$VAR/…`
- 무시하는 것: URL, `/dev/null` 같은 표준 장치, 실제로 존재하지 않는 절대 경로 단어(`sed`의 `/foo/d` 같은 패턴)
- **잡지 못하는 것**: 명령 치환(`$(…)`), 경로만 담은 변수, 스크립트나 다른 프로그램이 스스로 하는 일

> [!WARNING]
> `ask`는 작업 폴더 **안**의 변경은 묻지 않습니다. 프로젝트 안의 `bash` 명령도 위험할 수 있으니 중요한 서버에서는 Docker나 VM에서 실행하세요.

### 승인 흐름

![승인 카드. ① **확인 필요** 표시 ② 실행할 명령 전체를 보여 줍니다 ③ **거부**는 사유를 적을 수 있고 ④ **승인**을 누르면 실행됩니다](/assets/img/ui/approval.png)

1. 도구 호출 직전에 `approval_requested` 이벤트가 나가고 승인 카드가 뜹니다.
2. 사용자가 **승인** 또는 **거부**(사유 입력 가능)를 고릅니다.
3. 결정은 `approval_resolved`(`source`: `user` / `timeout` / `abort`)로 알려집니다.
4. 응답이 없으면 `PIPAYA_APPROVAL_TIMEOUT_MS`(기본 10분, 0이면 무제한) 뒤에 `Approval timed out`으로 거부됩니다.

![승인한 뒤에는 표시가 **완료**로 바뀌고 에이전트가 결과를 이어받아 답합니다](/assets/img/ui/approved.png)

대기 중인 승인은 `GET /approvals?sessionId=`로 보고 `POST /sessions/:id/approvals/:toolCallId`에 `{approved, reason?}`를 보내 결정합니다. 앱에서는 승인 카드의 버튼, 또는 단축키 *도구 실행 승인/거부*(기본 지정 없음)로 합니다. 승인 방식 전환 단축키도 있습니다 → [[shortcuts]].

## 경로 규칙

> [!WARNING]
> **현재 코드는 파일 도구의 경로를 작업 디렉터리로 제한하지 않습니다.** `read`, `write`, `edit`, `ls`, `grep`은 절대 경로나 `../`로 작업 폴더 밖을 다룰 수 있습니다. `safePath`가 원래 하던 검사는 커밋 `cb26464`("drop path restriction")에서 의도적으로 제거되어, 지금은 경로를 그대로 돌려줍니다. 밖으로 나가는 **변경**은 `ask` 정책의 승인으로만 통제되고, **읽기는 어떤 정책에서도 막히지 않습니다.**

| 도구 | 경로 처리 |
|---|---|
| `read` `ls` `grep` | 제한 없음. 승인 대상도 아님 |
| `write` `edit` | 제한 없음. `ask`에서 프로젝트 밖이면 승인 필요 |
| `bash` | 제한 없음. `ask`에서 위의 문자열 규칙으로 판단 |

서버 설정 `PIPAYA_RESTRICT_WORKSPACE=1`은 **세션의 `cwd`와 폴더 선택기, 기본 폴더**를 워크스페이스 안으로 제한할 뿐, 에이전트 도구가 읽는 경로를 막지는 않습니다.

격리가 필요하면 [[security]]의 Docker 구성을 쓰세요. 컨테이너 안에서는 에이전트가 볼 수 있는 파일시스템 자체가 제한됩니다.

## 안전장치

| 장치 | 값 | 설명 |
|---|---|---|
| 최대 모델 호출 | 한 실행당 200회 | `PIPAYA_MAX_RUN_TURNS`로 변경. 넘으면 "메시지를 보내 이어서 진행"하라는 안내와 함께 멈춤 |
| 반복 호출 감지 | 연속 6번 같은 호출 | 이름과 인자가 같은 도구 호출(턴 단위)이 6번 이어지면 중단 |
| 강제 종료 | 중단 요청 8초 후 | 멈추지 않으면 실행을 끊고 `aborted`로 마침 |
| 승인 시간 제한 | 10분 | 기본값 |
| `peer_send` | 한 실행당 10회 | 세션 간 무한 핑퐁 방지 |
| bash 시간 제한 | 기본 120초, 최대 1800초 | |

## 도구 호출과 이벤트

도구 실행은 `tool_execution_start` → `tool_execution_update`(출력 중간값, 저장 안 됨) → `tool_execution_end` 이벤트로 알려지고, 앱의 도구 카드에 상태가 표시됩니다: 준비 중, 승인 필요, 답변 필요, 실행 중, 완료, 실패, 거부됨, 실행 안 됨. 종료 코드가 있으면 함께 보입니다. → [[events]]
