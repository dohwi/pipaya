증상별로 원인과 조치를 찾아보세요. 먼저 `GET /health`와 서버 로그부터 확인하면 대부분 범위가 좁혀집니다.

## 처음 점검

```bash
curl http://<서버 주소>:8787/health                  # 서버가 떠 있나
TOKEN="$(< ~/.pipaya/token)"
curl -H "Authorization: Bearer $TOKEN" http://<서버 주소>:8787/activity   # 토큰이 맞나
journalctl --user -u pipaya -n 100                    # 최근 로그 (Linux)
```

## 연결

| 증상 | 원인과 조치 |
|---|---|
| 앱이 서버에 연결되지 않음 | 주소·포트 확인. 스크립트 기본 수신 주소는 Tailscale IP 또는 `127.0.0.1`. 다른 기기에서 쓰려면 `--host`에 Tailscale IP를 지정 |
| `연결 안 됨` 표시 | 서버가 꺼졌거나 네트워크 문제. `install.sh status` 또는 `/health` |
| `토큰 거부됨` / `401` | 토큰이 틀림. `cat ~/.pipaya/token`으로 다시 확인. 해지된 기기라면 QR로 다시 연결 |
| `앱 업데이트 필요` / `426 client_too_old` | 앱이 서버보다 오래됨. 앱을 업데이트 → [[updates]] |
| `403 admin_only` | QR로 연결한 기기 토큰으로 관리자 전용 경로를 부름. 관리자 토큰을 쓰기 |
| 브라우저에서 CORS 오류 | 웹 클라이언트 주소를 `PIPAYA_CORS_ORIGINS`에 추가 |
| 인터넷 경유 시 토큰 노출 경고 | `http` 주소입니다. Tailscale 주소나 `https`로 |
| QR 스캔이 `만료됐거나 이미 사용됐습니다` | 코드는 2분·1회용. PC에서 **새 QR** 만들기 |
| QR로 연결했는데 폰이 서버에 못 닿음 | 주소가 `localhost`. Tailscale이나 LAN 주소로 바꿔 다시 만들기 |
| `429` (연결 코드) | 잘못된 코드를 너무 많이 시도. 1분 뒤 다시 |
| 포트 사용 중 | `ss -ltn`으로 빈 포트를 찾아 `--port` 또는 `PIPAYA_PORT` |

## 모델

| 증상 | 원인과 조치 |
|---|---|
| 입력은 되는데 모델이 없음, "모델 연결" 버튼이 보임 | 연결된 모델이 없음 → [[models]] |
| 로컬 모델에 연결 안 됨 | 주소의 `localhost`는 **서버 머신** 기준. Docker면 `host.docker.internal` 사용 |
| 연결 테스트가 `401`/`403` | 키가 틀리거나 만료. 키를 다시 저장 |
| 모델/프로바이더 삭제가 `409` | 기본값이나 세션이 사용 중. 다른 모델로 바꾼 뒤 삭제 |
| 모델 ID가 `available: false` | 업스트림 모델 목록에서 사라짐. 연결을 새로고침하거나 다른 모델 선택 |
| 압축 모델 경고 "연결에 키가 없어 압축이 실패" | 그 연결에 키를 넣거나 다른 모델 선택 |
| 하위 에이전트 모델 경고 | 같음 |
| 추론 강도가 효과 없음 | 그 모델이 추론을 지원하지 않음 |
| 제목이 "New session"으로 남음 | 시스템 모델이 꺼져 있으면 첫 메시지 앞 60자. 설정은 [[models]] |

## 대화와 도구

| 증상 | 원인과 조치 |
|---|---|
| 메시지가 `409 session is busy` | 실행 중인 세션에 `prompt`를 보냄. `steer`나 `follow_up`으로 보내기(입력창은 자동) |
| 메시지가 `409` 압축 중 | 압축이 끝날 때까지 대기. 중지 버튼으로 취소 |
| 에이전트가 "Stopped after 200 model calls" | 한 실행의 모델 호출 한도. 메시지를 보내 이어서 진행. 한도는 `PIPAYA_MAX_RUN_TURNS` |
| 같은 동작을 반복하다 멈춤 | 연속 6번 같은 도구 호출 감지. 요청을 바꿔 다시 시도 |
| 승인 카드가 안 뜨고 멈춰 있음 | 다른 창(분할 화면)이나 다른 기기에서 승인 대기 중일 수 있음. 사이드바의 승인 대기 표시 확인 |
| 승인이 자동으로 거부됨 | 10분 무응답. `PIPAYA_APPROVAL_TIMEOUT_MS` 조정 |
| `"write" is disabled: this session is read-only` | 세션 정책이 `readonly`. API로 `approval`을 바꾸기 |
| `ask_user is turned off in the settings` | 설정 → 일반의 **질문 허용**이 꺼짐 |
| 도구 출력이 중간에 잘림 | 출력은 50KB, `read`는 2,000줄 상한. `offset`·`limit`로 나눠 읽기 |
| `bash`가 시간 초과 | 기본 120초(최대 1800). 긴 작업은 `timeout`을 늘리거나 백그라운드로 |
| `bash`에서 환경 변수가 안 보임 | 허용 목록 밖의 변수는 전달되지 않음. `PIPAYA_BASH_ENV=NAME`으로 허용 |
| `edit`이 "oldText was not found" | 공백·줄바꿈이 다름. 정확한 텍스트로 다시 |
| `edit`이 "matches more than once" | 주변 줄을 더 포함해 유일하게 만들기 |

## 입력창과 첨부

| 증상 | 원인과 조치 |
|---|---|
| 스크린샷이 이미지가 아니라 파일로 들어감 | 선택한 모델이 이미지를 못 봄(vision 없음) → [[composer]] |
| 9번째 이미지가 안 붙음 | 메시지당 8장 |
| 첨부가 `413 too_large` | 파일 1개 50MB, 합계 100MB, 요청 192MB를 넘음 |
| `#` 메뉴에 파일이 없음 | 제외 폴더, 5초 캐시, 20,000개 색인 한도 |
| `@` 메뉴가 비어 있음 | 이름 있는 다른 활성 세션이 없음 |
| `/xxx`가 전송되지 않음 | 모르는 명령은 모델에 보내지 않음. `/`로 목록 확인 |
| 큰 PNG의 배경이 검게 변함 | 600KB 이상은 JPEG로 변환됨 |

## 컨텍스트와 압축

| 증상 | 원인과 조치 |
|---|---|
| 압축이 `409` | 대화가 실행 중이거나 기록이 짧거나 승인·질문 대기 중 |
| 압축이 `502` | 요약 모델 호출 실패. 압축 모델과 키 확인 |
| 압축이 `501` | 이 서버가 압축을 지원하지 않음. 서버 업데이트 |
| 컨텍스트 표시가 `—` | 압축 직후라 아직 측정되지 않음. 다음 응답 뒤 갱신 |
| `AGENTS.md` 수정이 반영되지 않음 | 세션 첫 실행 때 고정됨. **새 대화**에서 확인 → [[agents-md]] |
| 스킬을 켜도 모델이 안 씀 | `description`이 모호함. "언제 쓰는지" 구체적으로 → [[skills]] |
| 스킬이 목록에 안 보임 | 이름 규칙 위반이나 `SKILL.md` 형식 오류. 스킬 창 맨 위의 경고 확인 |

## 터미널

| 증상 | 원인과 조치 |
|---|---|
| 터미널 만들기가 `403 terminals_disabled` | 서버가 `PIPAYA_TERMINAL=0` |
| `409` | 터미널이 서버당 16개 한도에 닿음 |
| 서버 재시작 후 터미널이 사라짐 | 터미널은 메모리에만 있음 |
| Windows에서 입력이 이상함 | Windows는 PTY가 아니라 파이프. 클라이언트가 입력을 에코함 |

## 알림

| 증상 | 원인과 조치 |
|---|---|
| 알림이 안 옴 | 앱 창을 보고 있으면 보내지 않음. 설정 → 일반의 **시스템 알림** 확인, **시험 알림**으로 구간 점검 |
| 폰에 푸시가 안 옴 | 서버에 FCM 자격 증명이 없거나 앱이 푸시 토큰을 등록하지 못함 → [[notifications]] |
| PC에 알림이 갔는데 폰에도 옴 | 의도된 동작: PC에서 읽지 않으면 폰으로 에스컬레이션 |

## 서버 운영

| 증상 | 원인과 조치 |
|---|---|
| 서버 업데이트 불가 | 응답의 `reason` 확인 (`disabled`, `not_git`, `unmanaged`, `detached`, `fetch_failed`) → [[updates]] |
| 업데이트가 `409 sessions_running` | 실행 중인 대화가 있음. 끝난 뒤 하거나 `force` |
| 업데이트가 `502 update_failed` | 의존성 설치 실패. 이전 버전으로 복구됨. 네트워크 확인 |
| 서비스가 로그아웃하면 멈춤 | `sudo loginctl enable-linger $USER` |
| 서버 확장이 동작 안 함 | `POST /server-extensions/reload` 후 `GET /server-extensions/errors` |
| DB 잠금·손상 의심 | 실행 중에 DB 파일을 복사했는지 확인. 서비스를 멈추고 백업에서 복원 |
| 디스크가 빠르게 참 | `.pipaya/uploads/` 첨부와 오래된 대화. 자동 삭제를 켜고 업로드 폴더를 정리 → [[operations]] |

## 확장

| 증상 | 원인과 조치 |
|---|---|
| 앱이 시작 직후 이상함 | 확장이 원인일 수 있음. 앱 주소에 `?extensions=off` 또는 설정 → 확장의 안전 모드 → [[client-extensions]] |
| 확장을 켤 수 없음 | 안전 모드가 켜져 있거나 패키지에 문제가 있음. 안전 모드 해제 후 확인 |
| 가져오기 실패 | 패키지가 256KB를 넘거나 모르는 필드가 있음. 오류 메시지의 `경로: 이유` 확인 |

그래도 해결되지 않으면 [저장소 이슈](https://github.com/dohwi/pipaya/issues)에 서버 버전(`/health`의 `version`), 앱 종류, 재현 순서를 적어 알려 주세요.
