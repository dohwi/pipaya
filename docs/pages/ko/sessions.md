세션은 대화 하나입니다. 각 세션은 자기 모델, 작업 폴더, 승인 정책, 기록을 따로 가집니다.

## 세션 레코드

| 필드 | 설명 |
|---|---|
| `id` | 세션 ID |
| `title` | 제목. 최대 200자. 처음에는 `New session` |
| `name` | `@`로 부르는 호출명 (예: 미나). 자동 배정 → [[orchestration]] |
| `purpose` | 이 세션이 맡은 일 한 줄. 시스템 모델이 작성. 최대 200자 |
| `cwd` | 작업 디렉터리 |
| `provider` / `model` | 사용하는 모델 |
| `thinkingLevel` | 추론 강도: `minimal` `low` `medium`(기본) `high` `xhigh` `max` |
| `systemPrompt` | 기본 프롬프트 대체. **첫 메시지 전에만** 지정 가능(이후 `409`). 최대 100,000자 |
| `tools` | 사용할 도구 목록. **첫 메시지 전에만** 지정 가능 |
| `approval` | `ask` `auto` `readonly`. 새 세션은 서버 기본 정책을 따름 |
| `parentId` | 분기 원본 세션 |
| `closed` | 닫힘 여부 |

`systemPrompt`와 `tools`는 첫 메시지 이후 고정됩니다.

## 만들기

`POST /sessions` 또는 앱의 **새 대화**({{Alt+N}}, `/new`). 앱에서는 새 대화를 시작하는 즉시 서버에 세션이 만들어져 사이드바에 나타납니다.

- `cwd`는 서버에 존재하는 절대 경로이거나, 기본 작업 디렉터리 기준 상대 경로(없으면 생성)입니다.
- 서버를 `PIPAYA_RESTRICT_WORKSPACE=1`로 띄우면 세션·폴더 선택기·기본 폴더가 모두 워크스페이스 안으로 제한됩니다. 그 밖의 `cwd`는 거부됩니다.

## 제목과 역할 자동 생성

- **시스템 모델이 없으면**: 첫 메시지를 공백 정리해 앞 60자로 자릅니다. 역할(`purpose`)은 비어 있습니다.
- **시스템 모델이 있으면**: 첫 메시지(최대 4,000자)와 최근 메시지(최대 2,000자)로 제목(2~6단어, 40자 이내)과 역할(80자 이내)을 JSON으로 만들게 합니다. 사용자 메시지와 같은 언어로 씁니다.

시스템 모델은 [[models]]에서 설정합니다. `/rename`으로 직접 바꾸면 그 제목이 우선합니다.

## 보내기 모드

| 모드 | 동작 | 조건 |
|---|---|---|
| `prompt` | 새 실행 시작 | 세션이 **대기 중**일 때만. 실행 중이면 `409` |
| `steer` | 실행 중인 작업의 다음 단계에 지시를 끼워 넣음 | 실행 중 |
| `follow_up` | 현재 실행이 끝난 뒤 처리하도록 대기열에 넣음 | 실행 중 |

입력창에서 실행 중일 때 {{Enter}}는 끼워 넣기, {{Alt+Enter}}는 대기열입니다 → [[composer]]. 대기 중인 메시지는 입력창 위 목록에서 개별 취소할 수 있습니다(`/cancel`, {{Alt+Q}}, `POST /sessions/:id/queue/cancel`).

그 밖의 `409` 조건: 압축 중인 세션에 보낼 때, 닫힌 세션에 보낼 때.

## 중단과 재시도

| 동작 | 설명 |
|---|---|
| 중단 (`/stop`, {{Escape}}) | 에이전트에 중단을 요청. 8초 안에 멈추지 않으면 실행을 강제로 끊고 `aborted`로 마칩니다 |
| 재시도 (`/retry`) | 마지막 응답이 `error` 또는 `aborted`로 끝났을 때, 그 응답을 버리고 다시 실행. 그 외 상태에서는 `409` |

## 분기 (fork)

`/fork`는 현재 지점까지의 기록을 복사한 **새 세션**을 만들고 원본은 그대로 둡니다. `/fork last`는 마지막 응답 직전에서 갈라집니다. API는 `POST /sessions/:id/fork`에 `atSeq`(그 `seq`까지 복사, 생략하면 전부)와 `title`을 줍니다. `/tree`로 분기 구조를 보고 이동합니다. 분기된 세션은 사이드바에 원본 아래에 묶여 표시됩니다.

## 닫기와 다시 열기

| 동작 | 설명 |
|---|---|
| 닫기 (`/close`, {{Alt+W}}) | 실행 중이면 중단하고 활성 목록에서 치웁니다. **기록은 남습니다** |
| 다시 열기 (`/resume`, {{Alt+O}}) | 닫은 대화를 포함해 목록에서 골라 열기 |
| 삭제 (`/delete`) | 영구 삭제. 되돌릴 수 없음. 메시지와 이벤트도 함께 삭제 |

닫힌 세션은 `@` 지목 대상에서 빠지고 이름도 다시 쓸 수 있습니다. 세션이 그룹에 속해 있었다면 닫거나 지울 때 그룹을 떠나고, 그룹이 2개 미만이 되면 그룹이 해제됩니다.

## 목록 조회

`GET /sessions?limit=&before=&closed=`

| 파라미터 | 설명 |
|---|---|
| `limit` | 1~200, 기본 50 |
| `before` | 이전 페이지의 `nextBefore` 커서 |
| `closed` | `true`: 닫힌 것만, `false`: 활성만, 생략: 둘 다 |

## 일괄 삭제와 자동 정리

설정 → 서버 → **대화** 화면에서 폴더별로 대화를 선택해 지울 수 있습니다. 한 번에 최대 500개이며, **실행 중이거나 승인·질문 대기 중인 세션은 건너뜁니다**(응답의 `skipped`).

서버의 자동 정리는 오래 쓰지 않은 대화를 알아서 지웁니다.

| 설정 | 값 |
|---|---|
| `enabled` | 기본 꺼짐 |
| `days` | 마지막 사용 후 며칠이 지나면 삭제할지. 1~3650, 기본 30 |
| `onlyClosed` | 켜면 닫은 대화만 삭제. 기본 꺼짐 |

서버 시작 30초 뒤 한 번, 이후 1시간마다 실행됩니다. 마지막 실행 시각·삭제 개수·지금 삭제 대상 개수를 화면에서 볼 수 있습니다. 실행 중이거나 답을 기다리는 대화는 나이와 상관없이 지우지 않습니다. API는 `GET`/`PUT /sessions/retention`입니다.

## 상태 보기

| 항목 | 위치 |
|---|---|
| 실행 중 / 승인 대기 / 질문 대기 | 사이드바 상태 표시, `GET /activity` |
| 스트리밍 중인 부분 메시지 | `GET /sessions/:id/status` (늦게 접속한 클라이언트용) |
| 토큰·비용 합계 | `GET /sessions/:id/usage` — `input` `output` `cacheRead` `cacheWrite` `totalTokens` `cost`(USD) `turns` |
| 적용된 AGENTS.md·스킬·시스템 프롬프트 | 대화 헤더의 세션 컨텍스트 → [[context]] |

> [!NOTE]
> 커스텀 연결에는 가격을 설정하지 않으므로 기록되는 비용은 0입니다. 무료라는 뜻은 아닙니다.

## 설계 메모

- 서버를 재시작하면 진행 중이던 실행은 중단되고 자동으로 이어지지 않습니다.
- 30분 동안 쓰지 않은 세션은 메모리에서 내려가며 다음 사용 때 DB에서 다시 올라옵니다.
- 같은 세션에서 동시에 두 실행은 돌지 않습니다.
