# 확장 개요

클라이언트 확장은 **앱을 다시 빌드하지 않고** 테마, 슬래시 명령, 입력창 버튼, 상태 표시, 패널, 헤더 게이지, 언어팩, 알림 규칙을 추가하는 방법입니다. 웹과 Tauri 클라이언트에 똑같이 적용됩니다.

> [!NOTE]
> 서버의 에이전트 도구나 모델 제공자를 바꾸는 확장이 아닙니다. 확장은 **클라이언트 화면**에만 영향을 줍니다. 서버 동작과 대화 원문에는 접근할 수 없습니다.

## 무엇을 할 수 있나

| 기여 | 만드는 방법 | 화면 위치 | 한도 |
|---|---|---|---|
| 템플릿 명령 | 패키지 `commands[]` | `/` 슬래시 메뉴 | 20개 |
| 코드 명령 | `sdk.commands.register` | 슬래시 메뉴 | 확장당 20개 |
| 입력창 버튼 | `sdk.composer.registerAction` | 입력창 아래 | 10개 |
| 패널 | `sdk.ui.registerPanel` | 우상단 런처 → 모달 | 확장당 5개 |
| 입력창 위젯 | 패널 `placement: 'composer'` | 입력창 위 접이식 박스 | 패널 5개에 포함 |
| 헤더 항목 | `sdk.navbar.set` | 헤더 우측 | 3개, 읽기 전용 노드만 |
| 상태 칩 | `sdk.status.set` | 입력창 아래 상태 줄 | 10개, 120자 |
| 테마 | 패키지 `theme` | CSS 변수 | 허용 토큰 목록만 |
| 언어팩 | 패키지 `locales` | 설정 → 일반 → 언어 | 확장당 5개 언어 |
| 알림 | `sdk.notifications.*` | 토스트 / OS 알림 | 10초에 5개 |
| 설정 폼 | manifest `settings` | 설정 → 확장 | 필드 20개 |

전역 한도: 확장 50개, 패키지 256 KiB, 코드 128 KiB, 설정 JSON 16,000자, 확장 저장소 32,000자, 로그 100개.

## 안전 모델

확장 코드는 앱 본체에서 **절대** 실행되지 않습니다.

```text
확장 JSON 패키지 ──parsePackage(엄격 검증)──► ExtensionHost
                                               │ enable()
                                               ▼
   앱 영역            ┌─ <iframe sandbox="allow-scripts"> (opaque origin) ─┐
                      │    └ blob Worker : `sdk` 주입, 코드 실행            │
                      └──────────────── MessagePort ───────────────────────┘
 Worker ─rpc(method, args)─► runtime.receive ─► host.request()   ← 권한 검사는 여기서
 host ─execute(token, arg)─► Worker 핸들러 (명령·액션·패널 이벤트)
```

- iframe에는 `allow-scripts`만 있고 `allow-same-origin`이 없어 앱의 DOM, `localStorage`, 토큰, Tauri API에 닿을 수 없습니다.
- Worker의 직접 네트워크, 외부 스크립트, 이미지, 하위 iframe, 폼 전송은 CSP로 막습니다. 네트워크는 `http` 권한을 통한 **호스트 대행 요청**만 가능합니다.
- 권한은 Worker가 아니라 **호스트에서** 검사하므로, Worker가 SDK를 우회해 메시지를 직접 만들어도 권한이 늘지 않습니다.
- 화면에 영향을 주는 것은 **검증된 데이터**(manifest, theme, commands, UI view tree)뿐입니다. HTML, CSS, URL, 함수, 이벤트 속성은 받지 않고, 호스트가 신뢰된 컴포넌트로 그립니다.
- 시작 5초, 명령 실행 10초, SDK 응답 5초 제한. 4초마다 하트비트를 보내 5초 내 응답이 없으면 중지합니다. 초당 메시지 200개, 대기 요청 100개, 동시 명령 20개를 넘길 수 없습니다.
- CSP가 적용되지 않는 WebView에서는 시작 전 canary 검사에서 걸려 **코드를 실행하지 않습니다.**

> [!WARNING]
> 브라우저 샌드박스는 OS 프로세스 격리나 메모리·CPU 할당량 보장이 아닙니다. 악의적인 대용량 메모리 할당이나 브라우저·WebView 취약점까지 막는다고 주장하지 않습니다. 검토하지 않은 확장은 실행하지 마세요.

## 설치와 수명주기

1. 설정 → **확장**에서 `.json` 패키지를 가져옵니다.
2. 패키지 정보와 요청 권한을 확인합니다. 가져온 패키지는 **비활성**입니다.
3. 활성화합니다.
4. 비활성화하면 그 확장의 명령·액션·상태·헤더 항목·이벤트 구독·테마가 해제되고 진행 중인 `http` 요청도 취소됩니다.

- **다른 확장은 자동으로 비활성화되지 않습니다.**
- 같은 ID를 다시 가져오면 그 확장만 교체하고 설정은 유지합니다. 새 권한을 요청하지 않고 실행 중이었다면 `교체하고 바로 실행`이 가능하고, 새 권한이 생기면 다시 동의해야 합니다.
- 설정 스키마가 있는 새 패키지는 설정을 **한 번 저장하기 전에는 활성화할 수 없습니다** (기본값은 미리 채워져 있으니 저장만 누르면 됩니다).
- 필수 설정이 비었거나 잘못됐으면 활성화가 거부됩니다.

### 서버 확장과 기기 확장

| | 서버 확장 | 기기 확장 |
|---|---|---|
| 속한 곳 | 연결한 서버 | 이 기기 |
| 서버를 바꾸면 | 목록이 바뀜 | 그대로 |
| 다른 기기에서 | 같은 서버면 보임 | 보이지 않음 |
| 저장 | 서버 `client_settings.extensions` | `localStorage` `pipaya.extensions.device.v1` |

같은 ID가 둘 다 있으면 기기 확장이 이기고 서버 쪽 사본은 읽을 수 없는 항목으로 보관됩니다.

## 문제가 생기면

- 설정 → 확장 → **안전 모드**: 모든 확장을 중지합니다.
- 시작 도중 새로고침되면 다음 시작에서 **그 확장만** 비활성화되고 나머지는 정상 시작합니다.
- 부팅조차 어려우면 웹 URL 끝에 `?extensions=off`를 붙입니다.
- 이전 버전이 저장한 패키지가 지금 검증을 통과하지 못하면 버리지 않고 `읽을 수 없음` 카드로 원본을 보관합니다. 원본 내보내기와 삭제를 할 수 있습니다.

## 지원하지 않는 것

확장 마켓·자동 다운로드·자동 업데이트, 서명·발행자 검증, npm 패키지, 임의 HTML·프레임워크 컴포넌트·CSS, 키보드 단축키 등록, 파일·셸·임의 네트워크 API, 서버 동작 변경, 대화 원문 접근.

새로 열려면 기존 권한으로 슬쩍 열지 말고 **명시적인 새 권한과 사용자 승인**을 추가해야 한다는 것이 원칙입니다.
