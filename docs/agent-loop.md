# 세션과 에이전트 루프

## 세션이란

세션은 하나의 대화 + 그 대화의 **고정된 실행 환경**입니다.

| 필드 | 설명 |
|---|---|
| `cwd` | 작업 디렉터리. 파일 도구는 이 밖을 열 수 없습니다 |
| `provider` / `model` | 사용할 모델 연결 |
| `thinkingLevel` | `minimal` `low` `medium`(기본) `high` `xhigh` `max`. `off`는 지원하지 않으며 기존 `off` 세션은 `medium`으로 이전됩니다 |
| `systemPrompt` | 기본 시스템 프롬프트. **첫 메시지 이후 고정** |
| `tools` | 켜 둘 도구 목록. **첫 메시지 이후 고정** |
| `approval` | `auto` / `ask` / `readonly` |
| `closed` | 닫힌 세션은 활성 목록에서 숨겨지고 나중에 다시 열 수 있습니다 |

기본 시스템 프롬프트는 짧습니다. 작업 디렉터리 안에서 도구로 파일을 보고 바꾸며, 작고 검증 가능한 단계로 진행하라는 내용입니다.

## 메시지 보내기: 세 가지 모드

`POST /sessions/:id/messages`의 `mode`:

| 모드 | 의미 |
|---|---|
| `prompt` | 한가한 세션에서 새 실행을 시작 |
| `steer` | **실행 중인** 에이전트에 끼어들어 방향을 바꿈 |
| `follow_up` | 지금 실행이 끝난 뒤에 이어서 처리할 메시지를 대기열에 넣음 |

상태가 맞지 않으면 `409`입니다(예: 실행 중인데 `prompt`). 아직 전달되지 않은 대기 메시지는 `POST /sessions/:id/queue/cancel`로 취소할 수 있습니다.

## 한 번의 실행

```text
POST /messages ──202──►  Agent 실행 시작 (run_started)
                           │
                  ┌────────▼─────────┐
                  │ 모델 호출(스트리밍)│── message_update (일시)
                  └────────┬─────────┘
                           │ 도구 호출?
                  ┌────────▼─────────┐
                  │ beforeToolCall   │── 승인 정책 검사 ─► approval_requested …
                  └────────┬─────────┘
                           ▼
                    도구 실행 ── tool_execution_update (일시)
                           │ 결과를 모델에 돌려줌 → 반복
                           ▼
                    message_end (영속, seq 부여) … run_finished
```

- 모든 완성된 메시지는 `message_end`에서 SQLite `messages`에 `seq` 순서로 **저장**됩니다.
- 실행이 끝나면 `run_finished`가 `{status, error, durationMs, usage}`와 함께 옵니다. 이 이벤트가 "한가해짐" 신호입니다.
- 실패하거나 중단된 실행은 `POST /sessions/:id/retry`로 다시 시도합니다. `POST /sessions/:id/abort`로 진행 중인 실행을 중단합니다.
- 한가한 세션의 메모리 상 에이전트는 5분마다 점검해 마지막 활동 후 30분이 지나면 내려갑니다. 기록은 DB에 있으므로 다음 메시지 때 다시 만들어집니다.

## 컨텍스트가 만들어지는 방식

### AGENTS.md는 첫 실행에 고정됩니다

에이전트의 시스템 프롬프트 = 세션의 기본 프롬프트 + 발견된 `AGENTS.md` 지침 + 켜진 스킬 목록입니다. 지침 탐색은 다음 순서입니다.

1. 서버 사용자 홈의 `~/.agents/AGENTS.md` (전역)
2. 파일시스템 루트부터 작업 디렉터리의 상위까지 각 `AGENTS.md`
3. 작업 디렉터리의 `AGENTS.md`

같은 실제 파일은 한 번만 넣고, 빈 파일은 넣지 않으며, 하위 폴더를 재귀 탐색하지 않습니다. 파일당 64 KiB, 합계 256 KiB 한도가 있습니다. 첫 실행 전에 보이는 것은 **미리보기**이고, 첫 실행 때 스냅샷이 저장되어 이후 바뀌지 않습니다. 대화 헤더의 파일 아이콘에서 실제 적용된 내용을 볼 수 있습니다.

### 스킬은 항상 최신입니다

AGENTS.md와 달리 스킬은 **현재 설정**을 따릅니다. 켜고 끈 결과는 진행 중인 세션에도 **다음 메시지부터** 적용됩니다. 켜진 세트가 실제로 바뀌었을 때만 시스템 메시지를 다시 쓰므로, 그렇지 않으면 제공자의 프롬프트 캐시가 유지됩니다. 자세한 내용은 [스킬과 지침](skills-context.md)을 보세요.

### 압축(compaction)

컨텍스트 창이 거의 찼을 때 오래된 메시지를 **요약으로 대체**해서 모델에게 보여 줍니다. 저장된 대화 기록 자체는 바뀌지 않습니다.

- 수동: `POST /sessions/:id/compact` (선택적으로 `customInstructions`). 실행 중이거나 너무 짧으면 `409`, 요약 모델이 실패하면 `502`.
- 자동: 설정 `auto`(기본 켬). 프롬프트를 보내기 전에, 컨텍스트 창에서 예약분(16,384토큰)을 뺀 지점(단, 창의 절반 아래로는 내려가지 않음)을 넘으면 실행합니다.
- 최근 약 20,000토큰은 원문 그대로 유지하고, 요약 출력은 최대 4,096토큰입니다.
- 요약을 쓸 모델은 설정할 수 있습니다. `null`이면 해당 세션의 모델을 씁니다.
- 결과는 `session_compactions` 테이블에 쌓입니다.

### 포크

`POST /sessions/:id/fork`로 특정 `atSeq` 시점까지의 대화를 복제해 새 세션으로 분기합니다.

## 서브에이전트 (`delegate`)

여러 파일을 뒤져야 하는 조사는 메인 대화에 파일 내용을 쏟아내지 않고 **읽기 전용 도우미**에게 맡길 수 있습니다.

- 도우미의 도구는 `read`, `grep`, `ls`뿐입니다. 파일을 바꿀 수 없고, `delegate` 자체가 없어 다른 도우미를 부를 수 없습니다. (이 목록을 넓히는 것은 보안 결정입니다.)
- 도우미는 **대화 내용을 보지 못합니다.** `task`에 필요한 맥락을 모두 적어 보내야 합니다 (최대 4,000자).
- 결과는 `path:line` 인용이 달린 300단어 이내의 보고서이고, 6,000자에서 잘립니다. 호출당 출력은 2,048토큰으로 제한됩니다.
- 설정(`GET/PUT /subagents`): 최대 10명, 각자 이름(`^[a-z][a-z0-9-]{0,39}$`)·설명·모델·도구·`maxTurns`(2–30, 기본 12)·추가 프롬프트를 가집니다. 모델이 `null`이면 호출한 세션의 모델로 돕니다. 기본 사고 강도는 `minimal`입니다.
- 쓰기 도구가 아니므로 `readonly` 세션에서도 허용됩니다.

보고서는 단서로만 취급하세요. 도구 설명에도 "인용된 줄을 직접 읽고 나서 코드를 바꾸라"고 적혀 있습니다.

## 세션 그룹

여러 세션을 분할 화면으로 나란히 보여 주는 이름 붙은 레이아웃입니다.

- 레이아웃은 이진 트리입니다. `pane`은 세션 하나, `split`은 영역을 둘로 나눕니다 (`row`/`col`, 비율 0.1–0.9).
- 그룹은 **2–8개** 세션을 담습니다. 한 세션은 최대 한 그룹에만 속합니다.
- 세션이 하나만 남으면 서버가 그룹을 해체하고 `group_deleted`를 보냅니다.
- 만들기: 사이드바에서 대화를 다른 대화 위로 끌어다 놓거나, `Ctrl+\`(오른쪽) / `Ctrl+Shift+\`(아래)로 현재 창을 쪼갭니다. 새 대화는 쪼갠 창과 같은 작업 디렉터리와 모델로 시작합니다.

## 오래된 세션 정리 (retention)

기본은 **꺼짐**입니다. 켜면 `days`(1–3650, 기본 30일) 동안 쓰지 않은 세션을 지우고, `onlyClosed`로 닫힌 세션만 지울 수도 있습니다. 서버에 저장되므로 모든 기기에서 같은 정책이 보입니다.
