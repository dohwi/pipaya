# 인증과 기기 토큰

## 두 종류의 자격 증명

| 자격 증명 | 만드는 방법 | 권한 |
|---|---|---|
| **관리자 토큰** | `HARNESS_TOKEN` 또는 `~/.pipaya/token`에 자동 생성 | 모든 API. 기기 토큰을 만들고 폐기할 수 있는 **유일한** 자격 증명 |
| **기기 토큰** (`hdt_…`) | 페어링 코드를 교환하면 기기마다 발급 | 일반 API. 다른 기기를 페어링하거나 토큰을 관리할 수는 없음 |

모든 API 호출에는 `Authorization: Bearer <token>`이 필요합니다. 예외는 `GET /health`와 페어링 코드 교환(`POST /pairing/redeem`)뿐입니다.

```bash
TOKEN="$(< "$HOME/.pipaya/token")"
curl -H "Authorization: Bearer $TOKEN" http://<server-ip>:8787/configuration
```

브라우저 `EventSource`와 WebSocket은 헤더를 못 붙이므로 `/events`, `/sessions/:id/events`, `/ws`에서만 `?token=`을 받습니다.

## 페어링 흐름

폰에 관리자 토큰을 넣으면 화면을 찍힌 사진 한 장으로 서버를 내줄 수 있습니다. 그래서 QR에는 토큰이 아니라 **일회용 코드**가 들어갑니다.

```text
PC(관리자)                     서버                       폰
   │  POST /pairing  ─────────►│ 코드 생성(해시만 보관)     │
   │◄──── code, expiresAt ─────│                            │
   │   QR 표시 ──────────────────────────── 스캔 ──────────►│
   │                           │◄── POST /pairing/redeem ───│ {code, name}
   │                           │ 코드 폐기, 기기 토큰 발급   │
   │                           │──────── hdt_… ────────────►│
```

- 코드는 **2분** 동안만, **한 번만** 쓸 수 있습니다.
- 서버는 코드의 SHA-256 해시만 **메모리에** 보관합니다. 재시작하면 모든 코드가 무효가 됩니다.
- 동시에 유효한 코드는 최대 5개이고, 새 코드를 만들면 가장 오래된 코드가 밀려납니다.
- 틀린 코드를 보내는 호출자는 분당 10회, 전체 합산 100회로 제한됩니다 (분산 추측 방지). 한 호출자가 시끄럽게 굴어도 주인이 잠기지 않도록 호출자별로 따로 셉니다.

## 기기 토큰

- 서버는 토큰의 **SHA-256만** 저장합니다. DB가 유출돼도 쓸 수 있는 값이 없습니다.
- 목록 `GET /devices/tokens`는 이름, 생성 시각, 마지막 사용 시각을 보여 줍니다. 마지막 사용 시각은 60초 단위로만 갱신합니다.
- `DELETE /devices/tokens/:id`로 폐기하면 **그 기기만** 즉시 끊기고, 열려 있던 SSE·WebSocket 연결도 닫힙니다. 관리자 토큰을 바꾸고 모든 기기를 다시 페어링할 필요가 없습니다.
- 기기가 스스로 붙이는 이름은 제어 문자를 제거하고 60자로 줄입니다.

## 알림용 기기 등록과의 차이

설정에 보이는 **기기 목록**에는 두 가지가 섞여 있어 헷갈리기 쉽습니다.

| | 기기 토큰 | 알림 기기 |
|---|---|---|
| 목적 | 접속 권한 | 알림을 어디로 보낼지 |
| 저장 | `device_tokens` | `notification_devices` |
| 폐기 | 토큰 폐기 → 접속 불가 | `DELETE /notifications/devices/:id` → 기기에 `device_revoked` 이벤트를 보내 스스로 보고를 멈추게 함 |

알림 쪽은 [알림](notifications.md)에서 설명합니다.
