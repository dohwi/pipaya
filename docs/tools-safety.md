# 도구와 안전

에이전트가 할 수 있는 일은 **도구**로 정해집니다. 서버는 도구를 정의하고, 경로를 제한하고, 변경 작업을 승인 정책에 태웁니다.

## 도구 목록

| 도구 | 변경 작업 | 설명 |
|---|---|---|
| `read` | 아니오 | 텍스트 파일 읽기. 최대 2,000줄 / 50KB, `offset`·`limit`으로 나눠 읽습니다 |
| `write` | **예** | 파일 만들기·덮어쓰기. 상위 디렉터리는 자동 생성 |
| `edit` | **예** | `oldText`가 파일에서 **정확히 한 번** 나타날 때만 `newText`로 교체 |
| `ls` | 아니오 | 디렉터리 목록. 디렉터리는 `/`로 끝납니다 |
| `grep` | 아니오 | 정규식 검색. ripgrep이 있으면 쓰고 없으면 grep. `glob` 필터 지원 |
| `bash` | **예** | 작업 디렉터리에서 명령 실행. 출력은 끝부분 50KB만 유지, 기본 타임아웃 120초(최대 1,800초) |
| `ask_user` | 아니오 | 요구사항이 정말 모호하거나 되돌리기 어려운 결정일 때 사용자에게 질문 (선택지 2–8개, 자유 입력 허용 여부) |
| `delegate` | 아니오 | 읽기 전용 서브에이전트에게 조사 위임 ([세션과 에이전트 루프](agent-loop.md)) |

세션을 만들 때 쓸 도구를 고를 수 있고, 첫 메시지 이후에는 고정됩니다. 기본값은 위 8개 전부입니다.

## 승인 정책

세션마다 하나를 고릅니다. 서버 기본값은 `HARNESS_APPROVAL`(기본 `ask`)입니다.

| 정책 | 변경 도구(`write` `edit` `bash`)의 동작 |
|---|---|
| `auto` | 바로 실행 |
| `ask` | 사용자가 승인할 때까지 **대기**. 거절하거나 시간이 지나면 자동 거부 |
| `readonly` | 항상 차단. 모델에게 "이 세션은 읽기 전용"이라는 이유를 돌려줌 |

- 정책은 서버의 `beforeToolCall` 훅에서 **호출 직전에** DB에서 새로 읽습니다. 그래서 어떤 클라이언트든 같은 규칙이 적용되고, 세션 중간에 정책을 바꾸면 곧바로 반영됩니다.
- 변경하지 않는 도구는 어떤 정책에서도 막히지 않습니다.
- 승인 대기 시간은 `HARNESS_APPROVAL_TIMEOUT_MS`(기본 600,000ms = 10분, `0`이면 무제한)입니다. 시간 초과, 실행 중단, 사용자 거절은 모두 `approval_resolved` 이벤트의 `source`(`timeout` / `abort` / `user`)로 구분됩니다.
- 승인 요청은 알림으로도 갑니다. 다만 **알림에서 바로 승인하지는 못합니다.** 알림을 누르면 해당 세션이 열립니다.

## 작업 디렉터리 격리

파일 도구는 세션의 `cwd` 밖을 열 수 없습니다.

- 경로는 **실제 위치(realpath)**로 판단합니다. 심볼릭 링크로 밖으로 나가는 시도도 막습니다. 아직 없는 파일을 만드는 경우에는 존재하는 가장 깊은 상위 디렉터리를 기준으로 판단합니다.
- 예외는 **켜져 있는 스킬 폴더**의 읽기뿐입니다. `read`만 스킬 폴더를 열 수 있고, 스킬을 끄면 그 폴더도 막힙니다.
- `HARNESS_RESTRICT_WORKSPACE=1`이면 세션 생성, 폴더 선택기, 기본 작업 디렉터리가 모두 `HARNESS_WORKSPACE` 안으로 제한됩니다. 기본은 꺼짐이라 서버의 존재하는 폴더는 어디든 쓸 수 있습니다.

> [!WARNING]
> `bash`는 샌드박스가 아닙니다. 서버 사용자 권한으로 실행되므로 셸을 통하면 `cwd` 밖도 건드릴 수 있습니다. 격리가 필요하면 Docker 샌드박스나 전용 사용자·VM을 쓰세요.

## `bash` 환경변수

`bash`가 실행하는 자식 프로세스는 서버의 환경변수를 **그대로 물려받지 않습니다.**

- `HARNESS_*`는 전부 차단합니다.
- 클라우드 자격 증명 같은 비밀은 허용 목록에 없어서 전달되지 않습니다.
- 전달되는 것: `PATH` `HOME` `USER` `SHELL` `TERM` `LANG` `TZ` `TMPDIR` 등 기본 셸 환경, 프록시와 인증서(`HTTP(S)_PROXY`, `SSL_CERT_*`), 툴체인 경로(`CARGO_HOME` `GOPATH` `JAVA_HOME` `NVM_DIR` …), 접두사 `LC_` `XDG_` `MISE_`
- 더 필요하면 `HARNESS_BASH_ENV=GH_TOKEN,FOO`처럼 쉼표로 **이름**을 추가합니다 (`HARNESS_`로 시작하는 이름은 무시됩니다).

## 인증과 네트워크 경계

| 항목 | 동작 |
|---|---|
| 토큰 | 관리자 권한. 24자 이상, 비교는 상수 시간 |
| CORS | Tauri 앱, 루프백, Tailscale(`100.64.0.0/10`, `*.ts.net`), 사설 LAN(RFC1918) 출처만 허용. 추가는 `HARNESS_CORS_ORIGINS` |
| 요청 크기 | 기본 2 MiB. 이미지가 든 메시지만 25 MiB |
| 로그 | `?token=` 값은 요청 로그에서 지워집니다 |
| 모델 URL | **서버가 직접** 요청합니다. LAN 주소도 허용되므로 신뢰하는 엔드포인트만 등록하세요 |
| 저장된 키 | 암호화되지 않은 채 `harness.db`에 있습니다 |

## 권장 구성

1. 혼자 쓰는 개인 서버: 호스트 설치 + Tailscale 바인딩 + `ask`
2. 낯선 코드를 다룰 때: Docker 샌드박스 + `HARNESS_WORKSPACE_DIR`로 해당 프로젝트만 마운트
3. 조사·리뷰 전용: 세션을 `readonly`로 만들고 `delegate`를 활용

취약점은 공개 이슈로 올리지 말고 `SECURITY.md`의 안내대로 비공개로 신고하세요.
