# 스킬과 지침

에이전트에게 규칙과 절차를 알려 주는 방법은 두 가지입니다. **AGENTS.md**는 항상 적용되는 지침이고, **스킬**은 필요할 때 읽는 절차서입니다.

|  | AGENTS.md | 스킬 |
|---|---|---|
| 내용 | 프로젝트·사용자 규칙 | `SKILL.md` 한 폴더 |
| 모델에게 | 시스템 프롬프트에 **전문**이 들어감 | 이름·설명·경로 목록만 알리고, 필요하면 모델이 `read`로 읽음 |
| 바뀌는 시점 | 세션 첫 실행에 **고정** | **다음 메시지부터** 현재 설정을 따름 |

## AGENTS.md

탐색 순서와 한도는 [세션과 에이전트 루프](agent-loop.md)에 있습니다. 요약하면 전역(`~/.agents/AGENTS.md`) → 루트부터 상위 디렉터리 → 작업 디렉터리 순이고, 하위 폴더는 보지 않습니다.

클라이언트의 대화 헤더에서 **세션 컨텍스트**를 열면 실제 적용된 파일, 경로, 범위, 바이트 크기, 경고, 전체 시스템 프롬프트, 활성 도구, 그리고 성공한 `read` 호출 기록(경로·횟수·줄 범위)을 확인할 수 있습니다. 읽은 파일 기록은 "과거에 읽었다"는 기록일 뿐 지금 모델 컨텍스트에 남아 있다는 보장은 아닙니다.

## 스킬

[Agent Skills](https://agentskills.io/specification) 규격을 따릅니다. `<이름>/SKILL.md`에 `name`과 `description` 프런트매터가 있어야 합니다.

```markdown
---
name: release-notes
description: 릴리스 노트를 쓸 때 읽는다. 커밋 로그를 사용자 관점 문장으로 바꾸는 규칙.
---

# 릴리스 노트
1. `git log` 로 이전 태그 이후 커밋을 모은다.
2. ...
```

### 어디서 불러오나

| 종류 | 위치 |
|---|---|
| 전역 | 서버 사용자의 `~/.agents/skills/` |
| 프로젝트 | 작업 디렉터리에서 git 루트까지(저장소가 없으면 `/`까지)의 `.pi/skills/`, `.agents/skills/` |
| 기본 내장 | 서버의 `server/builtin-skills/` (현재 `harness-client-extensions`, `harness-usage`) |

이름이 겹치면 **가까운 폴더 > 프로젝트 > 전역 > 기본 내장** 순으로 이깁니다. 같은 이름으로 내장 스킬을 덮어써도 경고가 없습니다. 읽지 못한 스킬은 건너뛰고 `GET /skills`의 `warnings`에 나옵니다. `disable-model-invocation: true`인 스킬은 목록에는 보이지만 모델에게는 제공되지 않습니다(수동 전용).

### 켜기 / 끄기

켜짐/꺼짐 상태는 스킬 폴더가 아니라 서버 DB에 있습니다.

- **전역 기본값**과 **프로젝트별 덮어쓰기**(git 루트 기준)가 있고, 실제 상태 = 프로젝트 값이 있으면 그것, 없으면 전역 값입니다. 기본은 모두 켜짐입니다.
- 프로젝트 덮어쓰기는 `enabled: null`로 지워서 전역 값을 다시 따르게 할 수 있습니다.
- 서버에 저장되므로 같은 서버에 연결한 모든 클라이언트가 같은 상태를 봅니다.

### 모델에게 어떻게 보이나

켜진 스킬은 시스템 프롬프트의 `<available_skills>` 블록(이름·설명·경로)으로 안내되고, 모델이 필요할 때 `SKILL.md`를 `read`로 엽니다.

- 켜진 세트가 실제로 바뀐 경우에만 시스템 메시지를 다시 씁니다. 그 외에는 프롬프트가 그대로라서 제공자의 프롬프트 캐시가 유지됩니다.
- 스킬을 끄면 목록에서 사라지고 그 폴더 읽기도 막힙니다. 이미 읽은 내용은 대화 기록에 남습니다.
- `read` 도구를 끈 세션에는 스킬을 알리지 않습니다 (읽을 수 없으므로).

### 직접 호출 (`/skill:이름`)

메시지에 `/skill:이름`을 쓰면 서버가 켜진 스킬의 `SKILL.md` 전문을 숨은 `<harness-hint>` 블록으로 그 사용자 메시지에 덧붙입니다(`disable-model-invocation` 스킬도 가능, 40,000자 제한). 시스템 프롬프트는 바뀌지 않아 프롬프트 캐시에 영향이 없습니다. 클라이언트는 `/` 메뉴에서 명령 뒤에 `스킬` 태그를 달아 보여 줍니다.

## 기본 내장 스킬: `harness-client-extensions`

클라이언트 확장 시스템을 수정하려는 에이전트를 위한 안내서입니다. `references/`에 `client/docs/extension*.md` 사본이 들어 있어서, 확장 관련 작업을 시키면 에이전트가 먼저 읽습니다. 원본 문서를 고친 뒤에는 `cd server && bun scripts/sync-builtin-skills.ts`로 사본을 맞춥니다. 어긋나면 서버 테스트가 실패합니다.

내장 스킬을 새로 추가하려면 `server/builtin-skills/<이름>/SKILL.md`를 만들면 됩니다.

## 기본 내장 스킬: `harness-usage`

이 하네스 자체의 설정법(서브에이전트 추가·수정, 전역/프로젝트 `AGENTS.md` 작성, 스킬 켜기/끄기)을 에이전트에게 알려 주는 안내서입니다. 사용자가 "서브에이전트를 하나 더 만들어 줘", "전역 AGENTS.md에 규칙을 넣어 줘"처럼 요청하면 에이전트가 먼저 읽습니다. 동작을 바꾸는 코드를 고쳤다면 `references/`의 한도와 설명도 같이 고치세요.
